## 第十一趟 · 欠账 ③④ 也清了（这一线今天没有剩下的活）

### ③ 状态存盘上那一档 —— 服务重启不再丢活

- 真身不是「换一个 saver」，是**接线**：`Checkpointer` 原来只认 `DATABASE_URL`（生产 Postgres），
  而这个部署**没有 Postgres** ⇒ `/health` 一直报 `memory` ⇒ `_recover` 读到空 `values`
  （`agent/service.py:4311`）⇒ **重启即丢活**。
- 现在认两个名字：**`SITEFORGE_CHECKPOINT_URL`**（优先）/ `DATABASE_URL`；两档 URL
  —— `postgresql://…` 与 `sqlite:////…`（**四个斜杠 = 绝对路径**，三个 = 相对）。
  **认不出来的 URL 当场拒**（`kind == "unknown"`，`get()` 直接抛）——
  不偷偷退回内存 saver：那会把「重启还在」说成「能恢复」。
- saver：`langgraph-checkpoint-sqlite`（一条依赖，自带 `aiosqlite` / `sqlite-vec`）+
  `runtime/` 里一个文件（那棵树是**挂载**的 ⇒ 换容器、重建镜像都不丢）。读走**第二条连接**
  （与 Postgres 那条同理；`setup()` 顺手开 WAL，读不被写挡住）。
- 这个部署已经按这条重建过容器（`docker run … -e SITEFORGE_CHECKPOINT_URL=sqlite:////opt/siteforge/runtime/checkpoints.sqlite`，
  README 里那段也补了），`/health` 现在报 `sqlite`。
- **实测**（不是「应该行」）：`POST /run` 让它停在第一道闸 → `docker restart siteforge` →
  `GET /job/{id}` **照样 `waiting`、停在同一个闸上**（改之前这一步就没了）→
  `reply {"action":"stop"}` 老实收摊（`human_stop`，没碰页面）。
- 测试：`tests/test_sqlite_checkpointer.py`（**默认就跑**，不依赖外部服务）：URL 分档 /
  两个环境名的优先级 / 认不出就拒 / 换连接接着跑（探路不重来）/ 账本三个 dataclass 从文件回得来 /
  服务换一个 app 之后同一个 job 还接得下去并交付。
- 顺带修一条**陈旧断言**：`tests/test_pg_checkpointer.py` 里一直写着第一道闸是 `intake`，
  而那道闸 2026-09-20 就换成 `explore` 了 —— 它是 **skip** 的用例，所以一直没人发现；
  今天起了个一次性的真库跑了一遍才现形（顺便也验了 Postgres 那条路没被我改坏）。

### ④ 生成器按站特性选形态

- 判据**只有一条，而且是量到的**：账本里有多少个状态共用同一个 `url_contains`
