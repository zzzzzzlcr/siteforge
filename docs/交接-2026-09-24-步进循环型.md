## ★★ 环境那一课（我踩了一小时，下一个别再踩）

**Bit 窗口的正确开法在仓里**：`skills/bit-window/SKILL.md` —— **动手前先读那一页**。
今天五趟「全哑」全是因为跳过了它的第 ② 步：

```
① 拉链   → :1081 的 gost（**绝不碰** :1080，那是生产的）
② 配窗口 → 直接 POST /browser/update（**不是** bit.sh update！）—— **必须在 open 之前**；
           它是**整条记录**更新 ⇒ 只给部分字段会被拒、还会把代理配置抹掉 ⇒
           先 GET /browser/detail（今天量到 126 个键）改完**整条写回**
③ 开窗口 → POST /browser/open {"id":bit_id, "args":[…], "queue":true}
           ★★ args 里必须有 --remote-debugging-address=0.0.0.0（和 --remote-debugging-port=61129
           / --remote-allow-origins=* / --disable-session-crashed-bubble）—— 原话在
           `agent/service.py:1179-1184`。**args 给空表 ⇒ 调试口绑在 worker 的 127.0.0.1**
           ⇒ 外面 TCP 连不上、CDP 回「Browser or page was closed」，而 `pids/alive` 照样说活着 ✗
           （手册：「alive 与 close 都可能骗人，开完必须回读」）
④ 干活   → 用 `common.CDPHelper`（产物走的就是这条路）
⑤ 收工   → POST /browser/close 看 `.success` ⇒ 再 POST /browser/pids/alive **验死**（空 dict 才算）
```

⚠️ **另一条**：手册点名「**孤儿窗口**」是最贵的坑（半启动的窗口吃内存 ⇒ 新 open 报 95% ⇒ 死锁；
实测 3 周 6174 次失败 ≈ 325 单空转）⇒「**重开之前先看 worker 的余量；连着失败就别硬开**」。
今天这十来次开/关是在那条线附近走的 ✗。
