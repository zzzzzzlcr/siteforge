# 缺陷单（2026-10-12）：「选国家」选错了 —— `cdp form --strict` 给影子树里的元素**改写出一条不存在的地址**

**一句话**：`cdp form --strict` 那一路会把命中的元素**改写**成 `strictPickJS` 里 `pathOf()`
造出来的地址；而 `pathOf` 沿 `parentElement` 往上走，**影子边界上 `parentElement` 是 null**
⇒ 给影子树里的元素造出 `html>input:nth-of-type(1)` 这种**根本不存在**的地址 ⇒ CLI 拿这条
**改写过的**地址去填 ⇒ `scroll mouse wheel failed: element not found`（元素明明就在屏幕上）。

后果不是「那一步没做成」那么轻：产物一失败就掉进「**重新 observe + 按意图重找**」那一支，
而那个搜索框在账本里**没有任何身份信号**，重找按意图猜（把握 0.50）⇒ 把该填进搜索框的
「United States」填进了 **First Name**；列表因此没被过滤，下一步那根「列表里第 n 个」的地址
点到的就是字母序第一个国家 ⇒ **真发出去的报名表上，Country of Residence 是 Albania**。

**③ 根因那一行**（`internal/form.go::strictPickJS`）：

```js
function pathOf(el){
  try { if (el.id) return '#' + CSS.escape(el.id); } catch (e) {}
  var parts = [], cur = el;
  while (cur && cur.nodeType === 1 && cur !== document.documentElement) {
    ...
    cur = cur.parentElement;      // ← 影子边界上这里是 null
  }
  return parts.length ? 'html>' + parts.join('>') : '';   // ⇒ html>input:nth-of-type(1)
}
```

`cmd/form.go`：`picked, err := client.StrictPick(...)` → `if picked != "" { selector = picked }`
—— 改写过的地址**替换**了原来那条（原来那条是对的）。

> **有 id 的元素踩不到**（`pathOf` 第一句就返回 `#id`）。真站那个搜索框**没有 id**，
> 只有 `placeholder="Search..."` —— 这一条是复现的钥匙，夹具因此**刻意不给 id**。

## 三、连带：为什么最后「国家错了」

1. 第 9 步（填搜索框）**没成** ⇒ 列表没被过滤（175 项全在）；
2. 重找把值填进了 `#firstname`（账本里那一步的 `text/label/hint/placeholder` 全是 `None`，
   重找只能猜，日志原话「账本里没有可比的身份信号，把握 0.50」）；
3. 第 10 步记的是「列表里第 n 个选项」（`#radix-_r_4_ > … > button:nth-of-type(1)`）——
   在**没过滤**的列表上，那就是字母序第一个（Albania / 上一趟 Angola）；
4. 站点收下了这个国家，所以整趟照样走到 OTP 页 —— **判据看不见值错**（自测判「过没过」不看值）。

⇒ 所以「修好第 9 步」= 两条毛病一起消失：同一根地址在**过滤后**（只剩 1 项）点的是唯一那项。

## 四、已修（2026-10-12）

**落点一：`tools/cdp/internal/form.go`**

- `strictPickJS().pathOf()`：元素在**影子树里**（`el.getRootNode() !== document`）⇒ 返回**空串**
  = 「这条改写不了，用原来那条」。调用方 `if picked != "" { selector = picked }` 本来就为
  「给不出更好的」留了这一格（`pickUnique` 命不中时也回空串）。
- `pickUnique()`：命中多个、按字段身份认出的那一个**在影子树里**（`sel == ""`）⇒ **大声失败**。
  这条闸的承诺是「**宁可不填，绝不填错**」；照原样返回 = 拿那条不唯一的地址再赌一次，违背的正是它。

**落点二：`agent/template.py`（产物骨架）—— 「**没找到先等一等**」**

声明里那根地址**没找到**（不是被盖着）时，先等一等、**重试同一根地址**
（`NOT_FOUND_WAIT_SECONDS = 6.0`，按步共用一笔预算；`NOT_FOUND_POLL_SECONDS = 0.6` 重发一次），
等到头还没出来就把第一次那个失败原样交回去 —— 换候选 / 重找 / 整组重走一个字不变。

⚠️ 说清楚：**这一格不是本单的修复**（本单第一次就失败，日志里没有「等了」—— 元素一直在屏幕上，
是 `--strict` 那条命令本身在报找不到）。它护的是**另一类**：元素**真的还没渲出来**的页面
（真站上有过：那一页当时还没 `readyState=complete`）。留着是因为「重找」那条路**会猜错**
（本单就是），多等一笔比猜一次便宜。测试里默认关掉（`tests/test_template.py::_load`），
免得几十条「故意让选择器挂掉」的用例每步白赔 6 秒。
