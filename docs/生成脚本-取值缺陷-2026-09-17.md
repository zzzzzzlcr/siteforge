# 生成脚本的取值缺陷（模板级）

**日期**：2026-09-17
**范围**：siteforge 产出的站点脚本（`forms/sites/*.py`）与生成它们的模板
**性质**：**模板级缺陷** —— 不修的话，每生成一个脚本就带一遍

---

## 一句话

**资料明明在手上，脚本读不到，就静默换一个随机值填上去 —— 而那个随机值可能是另一个国家的格式。**

---

## 现象（生产实测，task 26005216）

站点回「不是 US 资料」。查下来：

| | |
|---|---|
| 生产的 form 数据里**有** | `postal_code: "32084"`（**有效美国 ZIP**） |
| 脚本**填进去的** | `SW1A 1AA`（**英国邮编**） |

脚本**没有任何一步出错**，也没有任何一行日志说它换了值。

---

## 原因一：取值认单个 key，不认别名

脚本里 `source: 'postcode'` → `self.form_data.get('postcode')` → **取不到**，
因为生产数据的键是 `postal_code`。

**JSON 那条路早就有别名表**（`form_executor/variable_resolver.py:20`）：

```python
PROFILE_ALIASES = {
    "first_name": "first_name", "firstname": "first_name",
    "full_name": "full_name", "name": "full_name",
    "zipcode": "zip", "postal_code": "zip",
}
```

**⚠️ 但请先看这条更正**：这张表**只有 5 条**，**没有电话、没有 `username`**。
所以「py 这边共用它」能修**邮编**那一格，**修不了电话和姓名那两格**（见原因三）。
共用是对的，但**要先把表补齐**。

同一批对不上的键：

| 脚本要的 `source` | 生产数据的键 | 别名表里有吗 |
|---|---|---|
| `postcode` | `postal_code` | ✅ 有 |
| `phone` | `phone_number` | ❌ **没有** |
| `full_name` | 合在 `username` 里 | ❌ **没有** |

**py 这边今天的写法是各写各的** —— 64 个脚本里只有 2 个有专门的取值函数，
其余散在 42 处内联表达式里，写法各异。有脚本直接写死
`get("postal_code", "M5V 3L9")` —— **加拿大邮编写死在美国站上**。

**⚠️ 而模板里一条别名处理都没有** —— 在 `agent/template.py` 里 grep
`ALIAS|alias|postal_code|phone_number|username`，**零命中**。
所以找不到别名这件事**不是某个脚本写漏了，是生成器压根没这个概念**。

---

## 原因二：随机池按模板来源国，不按站点国家

gowizard.py 的池子（`forms/sites/gowizard.py:190-194`）：

```python
POSTCODES = ["SW1A 1AA", "NN3 3AQ", "M1 1AA", "B1 1AA", "LS1 1AA", "G1 1AA"]   # ← 英国
US_STATES = ["California", "Texas", "Arizona", "Florida", ...]                  # ← 美国
PHONES    = ["07936567874", "07700900123", "07400123456", "07911123456"]        # ← 英国
```

**抄了一半**：州是美国的，邮编和电话是英国的。

**⚠️ 而且这不是脚本抄错 —— 模板自己就是这么写的**（`agent/template.py:324-331`）：

```python
FIRST_NAMES = ["James", "John", "Robert", "Michael", ...]
POSTCODES   = ["SW1A 1AA", "NN3 3AQ", "M1 1AA", "B1 1AA", "LS1 1AA", "G1 1AA"]   # ← 英国
US_STATES   = ["California", "Texas", "Arizona", "Florida", ...]                 # ← 美国
PHONES      = ["07936567874", "07700900123", "07400123456", "07911123456"]       # ← 英国
```

**gowizard.py 那份是模板的逐字副本。** 所以：

- **改模板** → 以后生成的脚本不再带这个病
- **已生成的脚本**（gowizard.py 已交付）→ 各自还带着副本，要单独改

**美国站就该用美国 ZIP / 美国电话。** 池子跟着站点国家走。

## 原因三：掉到兜底时**完全静默**

`forms/sites/gowizard.py:1466-1477`：

```python
def _fill_value(self, fill, step):
    source = fill.get("source")
    if source:
        given = str(self.form_data.get(source) or "").strip()
        if given:
            return given
    candidates = list(fill.get("fallback") or [])
    if not candidates:
        self.log.warning(...)          # ← 只有「连随机池都空」才出声
        return ""
    pick = random.choice(candidates)   # ← 取不到资料就直接随机，一行日志都不打
    ...
```

**唯一的 `warning` 是「连随机池都是空的」那一种。**
「资料在手上、我没读对」这件事 —— **静默**。

**模板里是同一个形状**（`agent/template.py:1163-1173`，连 `:360` 那句注释都逐字一样）：

```python
def _fill_value(self, fill, step):
    """这一步填什么：先读 --form-file 里的键，没有就用 fallback 里的一个随机值。"""
    source = fill.get("source")
    if source:
        given = str(self.form_data.get(source) or "").strip()
        if given:
            return given
    candidates = list(fill.get("fallback") or [])
    if not candidates:
        self.log.warning("[%s] 「%s」既没有 form-file 的值也没有 fallback", self.cid, source or "?")
    pick = random.choice(candidates)
```

所以脚本自己也不知道自己填错了国家。**这正是它能一路错到生产的原因。**

内联那种写法更彻底：

```python
fn = (p.get("first_name") or (p.get("username","").split()[0] if p.get("username") else "")) or random.choice(FIRST_NAMES)
```

**纯表达式，结构上就没有位置可以打日志。**

---

## 要改的三条

### ① 取值认别名 —— 先把别名表补齐，再共用

- **别用单个 key 查**；py 与 JSON 两条路**共用同一张表**，不要再各写各的
- **表要补齐**：`phone_number → phone`、`username → full_name / first_name / last_name`
  （今天这张表**没有**这三条，只共用它等于没修电话和姓名）
- 消除写死的国家值（`get("postal_code", "M5V 3L9")` 那种）

### ② 随机池按站点国家

美国站用美国 ZIP / 美国电话。**池子跟着站点走，不跟着模板走。**

### ③ 掉到兜底时必须出声

打一行，例如：

```
「postcode」没从 form-file 取到，用了随机值 SW1A 1AA
```

**这一行能让人当场发现键名对不上，而不是等站点拒收。**

---

## 还有一条：先看格式，再决定用不用

**就算键名对上了，格式不对照样被拒。**

实测（LPA 那站）：生产给的是美国号 `5413017650`，**站点要英国手机** —— 键名没错，格式不对。

**判据应该是「像不像这个国家的格式」，不是「数据里有没有」。**
