# 缺陷单（2026-10-09）：「点了也不动」—— 悬浮窗盖住落点，而唯一能发现它的判据是哑的

**一句话**：产物点了一个**在页面上、href 也对、量的时候头顶上还是它自己**的元素，页面却纹丝不动 ——
因为 `cdp click` 自己会先把元素滚进视口再点，**滚完之后那一点已经落进一块 `z-index: 999999` 的
fixed 悬浮窗面板里**；而这一帧的落点判据恰好是 `landing_blind`，谁都不喊。

**环境**：8100（`siteforge-222`），`job-11e0e99d310d`（2026-10-09 19:19 起的那一单，站点 `kotzheating`）。
这一单体感：**现场看窗口一直停在首页不动**。

---

## 一、现象

自测基线（第 1 遍）第 4 步 —— 账本里那条「点 `Schedule Online`」：

```
step 4 click「Schedule Online」 ok=true  prog=false
       sel=#content>…div:nth-of-type(6)>…>a:nth-of-type(1)   level=2（重找那条）
       recovery={"primary_selector":"#content>…div:nth-of-type(12)>…>a:nth-of-type(1)",
                 "resolved_by":"text+role+near","confidence":1}
       note=点了「Schedule Online」（换了第 3 个找法才找到）
            （这一帧的落点判据用不了：跨站子帧里它不触发）；页面没有变化
step 4 click「Schedule Online」 ok=true  prog=false          ← 整组重试，这一下用的是**账本首选**（level=0）
       note=点了「Schedule Online」（这一帧的落点判据用不了：跨站子帧里它不触发）；页面没有变化
step 5~16  **整组跳过**：这一页不像「contact」那个状态（地址里没有 https://kotzheating.com/contact/）
```

⇒ 页面一直停在首页 ⇒ 后面**填表那一整组全被跳过**（跳过 = 没做）⇒ 这一遍的结论是「没走到成功」。

**间歇性**（同一族选择器、同一步）：**17:43 那版产物跑出来的是 `prog=true`**（那一下真推动了页面）；
这一版是 `prog=false`。差别不在选择器，在那块面板**当时开没开**。

## 二、证据

**① 元素本人在**（真页面量的，2026-10-09 19:26）：

```
a.elementor-button.elementor-button-link  [320×69 @20,237]  href=https://kotzheating.com/contact/
txt="Schedule Online"   pos=static z=auto pe=auto
中心 [180,272] → elementsFromPoint 栈顶 = span.elementor-button-text（它自己的后代）
⇒ top_is_self: true      ← **量的时候，那一点上是它自己**
```

**② 浮着的东西**（同一次量的，`position: fixed` 且 >20px）：

```
div#agency_bot_option_2_options.s-b-container.openOptions   255×339 @85,333    z-index 999999   ← 悬浮窗面板，**开着**
div.op2-close                                                35×42  @321,301

div.cc-revoke.cc-bottom「Cookie Policy」                     113×40 @48,717     z=9999
```

## 三、根因（这一段是推断，依据在上面两条之间）

1. **量点与落点不是一个点**。`_covered_by` 量的是**当下滚动位置**下、元素中心的命中栈；
   而 `cdp click` 自己会 `ScrollToElement → ScrollIntoView → 点中心` —— **滚动把它挪进了那块
   fixed 面板罩着的区域**（面板 255×339 钉在视口 [85,333]–[340,672]，正是「滚进视口」最容易落脚的地方）。
2. **唯一能发现它的判据是哑的**：这一帧回执里是 `landing_blind`（「跨站子帧里它不触发」）——
   现在它只是 note 里一句括号，**不参与判据**（`_landing_say` 只把它说给人听）。
   于是现场只剩 `ok=true / progress=false` 这一对，看着像「点上了，页面没动」。
3. **这一版账本里没有 `goto /contact/`**（17:43 那版有）：整条路全靠这一下点击把页面带过去，
   一旦这一下不落地，`contact` 那一整组就因地址对不上被跳过 —— **一处不落地 = 整组废**。

⚠️ 与 `fix-when-cut-report.md` §5 / §7.4 是**同一扇窗的两面**：
那边是「重放时去点它的 ✕（不存在 ⇒ 重找落到了 Submit）」，
这边是「它开着的时候，把我要点的正文元素盖住了」。

## 四、建议（判据怎么改，人来定；这里只摆候选）

| # | 改哪儿 | 怎么改 | 代价 |
|---|---|---|---|
| a | 产物 `_covered_by` | 把「滚进视口」并进判据：**先滚 → 再量 → 再点**（现在量在滚之前） | 每步多一次测量；换来「量过的点 = 点的点」 |
| b | 同上 | 或把量点交回 cdp：**它刚滚完，最清楚落在哪**（回执里已经有落点那一格） | 要 cdp 那侧把「落在谁身上」也回出来 |
| c | cdp 落点判据 | `blind` 不许当「没事」：至少把它记成一格（与 `progress=false` 合成「可疑点击」），让产物有机会换候选 | 改判据要人来点头 |
| d | 重放前 | 先收拾这一族 fixed 面板（`openOptions` 是**开着**的）：开工前统一关掉，或让站点/我们别让它压正文 | 面板有时是站点自己的弹窗（关不关得掉要看站） |
