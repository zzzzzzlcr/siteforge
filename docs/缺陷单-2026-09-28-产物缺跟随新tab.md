# 缺陷单（2026-09-28）：py 产物缺「点完之后跟新 tab」这一手

**给谁**：生成侧 / 引擎那一条线（`agent/template.py` 的产物骨架、以及自测那条线）
**严重度**：高（一整单全挂，且现场看不出来）
**状态**：未修（本次只加了现场记录，没改行为）

## 现象

点击打开了**新页 / 新 tab**（`target=_blank`、`window.open` 那一类），而脚本**还在老页上**
找元素 ⇒ 那一步报「没找到元素 / 页面没有变化」⇒ 后面每一步都错 ⇒ 整单挂掉。
现场只留一句「没找到元素」，**判不出**「其实是切页没跟上」。

## 证据

| # | 证据 | 在哪 |
|---|---|---|
| ① | 生产 8 单日志里同一个形状（点了、页面没动、下一步找不到元素） | 运营提供（2026-09-28） |
| ② | 复现站点：`georgiapower` 那一单（撞的就是这条） | 交接文档 + 那一趟 trace |
| ③ | **JSON 执行器那边早就有这一手**：`2215c16 feat: target=_blank 点击认出新 tab 并跟随 —— 生产此前完全没有这套逻辑` | git 历史 |
| ④ | py 产物侧**没有**任何 `targets` / `active` 的调用（grep 零命中） | `agent/template.py` |

## 为什么自测没拦住（两处「运气」叠在一起）

1. **自测跑的是裸 URL**（不是真实广告 URL）⇒ 落地页与跳转链跟生产不是同一条，
   那一跳新开 tab 的分支根本走不到。
2. **自测那个运行环境里，新 tab 会自动激活**（同一个窗口里，cdp 的连接就落在新 tab 上）
   ⇒ 脚本「看起来」跟上了 ✗。

⇒ 两条建议（与缺陷同等重要）：**自测要用真实广告 URL**；并且**在「重放模式」下也过一遍**
（不是只在 runner 那个环境里跑）。

## 建议的修法（py 产物侧）

点击之后加一手（`target=_blank` 的语义照抄 JSON 执行器那条先例）：

1. 点之前记下 `cdp targets` 里的页 id 集合；
2. 点之后再看一次：**多了新页**（或那个 `target=_blank` 的目标出现）⇒ `cdp active --target <id>`
   切过去 ⇒ 之后的读/写都相对这一页（`frame_id` 那一套照旧）；
3. 切不过去就**如实记**（「点开了新页但没跟上」写进 trace），**不许**当成「这一步做成了」——
   这正是本项目最贵的那类谎。

⚠️ 与「点到浮层上」同一条纪律：**动作成功 ≠ 页面到了**。切页这一下属于「到了吗」那一半。

## 附：本次已经加好的「现场记录」（不是修缺陷，是为了下次不用开窗）

`agent/template.py` 的失败现场（`_SCENE_JS` + `_tabs_now`，2026-09-28）现在会录：

- `dpr` / `vw,vh` / `ua`（窗口与指纹一致不一致，一眼可见 —— 顺带治
  「`cdp screenshot` 报 图 984 vs 视口×dpr 2952」那种只能靠开窗猜的问题）；
- `tabs`：**当时所有页/tab 的 URL + 标题 + 哪个是 active**（`cdp targets`，只读、一次调用）。

这两样只**记录**、不改行为 ⇒ 下一次这类问题，trace 里就能直接判，不必开窗复验。
