# 根因库（2026-10-14 起）

**一句话**：每份缺陷单**属于哪个根因**、**那一刀修在哪儿**。**同一个根因攒到第 3 份，就该治工具层，别再治站。**

## 为什么有它

2026-10-13 那次统计给的判据：**「同根因 ≤ 2 次」**——`17 缺陷单 / 32 提交（操作层 ~59%、
生成层 ~35%，**遮挡类第 3 次超阈值**）⇒ 建议先落根因计数 + 停止闸`。
**那条建议当时没落**，于是「修不完」的感觉一直在，而没人说得清是哪一个根因在重复。

## 规矩（四条）

1. **一张单一行**，`根因` 那一格重复写（好数、好加、好改）。份数由 `tools/rootcause.py` **算**，不手写（手写会锈）。
2. **不自动分类**。根因是**人打的**——从标题猜根因，正是 2026-10-14 栽过的那种错
   （自测报告里一句固定文案「打折叠 / 遮挡 / 坐标假设」让 46 个普通步骤被算成了「弹窗」）。
3. **`修在哪` 是承重的一格** —— 四档的**寿命完全不同**：

   | 值 | 住哪儿 | 重出这个站，还在吗 |
   |---|---|---|
   | `骨架` | `agent/template.py`（所有产物共用） | **在**，而且**所有站都有** ← 真·治一类 |
   | `生成侧` | `agent/browser_agent.py` / `lint.py`（影响「录进去什么」、闸） | 在（新探索的单生效） |
   | `cdp` | `tools/cdp`（Go 二进制） | 在（独立生命周期） |
   | **`产物`** | **只在 `forms-*/sites/<site>.py` 那一份里** | **丢**——重出就没了 ← **就是「修站」** |
   | `还没治` | —— | —— |

   多档用 `+` 连（`骨架+生成侧`）。**工具认不出别的字会点名**，防这格悄悄漂。

4. **`覆盖它的用例`** 空着 = 治了也没东西盖着。跟 `修在哪` 是两件事，别混。
