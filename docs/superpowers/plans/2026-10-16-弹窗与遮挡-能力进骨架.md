# 弹窗与遮挡「能力进骨架」实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把「遇到遮挡/弹窗怎么办」这套能力从固定步骤表骨架搬进循环型骨架（并让两套骨架**同源**），使**以后生成的每一份产物**都自带它。

**Architecture:** 判据与探针 JS **只写一份**（留在 `agent/template.py`，`agent/template_loop.py` 本来就 `from agent.template import …`，**无环**）；循环型骨架只加**挂点**与**报文**（每轮前 / 每次 `click`·`fill`·`pick_option` 前 / 动手后复核）。钩子表加一行「广告 creative」（判据由 kotzheating / blavity 两份产物试出）。站点专有的东西**只许作为数据**（表里一格 / 账本一行），不许写进骨架代码。

**Tech Stack:** Python 3.11 + CDP（`cdp` MCP / `tools/cdp`）+ pytest；产物是**自包含**的 .py（生产里单独跑，不能 import 本仓任何东西）。

**Spec:** `docs/superpowers/specs/2026-10-16-弹窗与遮挡-能力进骨架-design.md`（**先读它**：§3.3 那条待验假设与 §3.6 那条分界是本计划的全部依据）

## Review Focus

（spec 没说、但一定会遇到的输入；每条都要有任务里的用例钉住）

1. **跨域子帧里量不到落点** —— 10-09 那单的根因就在跨站子帧：`elementFromPoint` 那层够不着。期望：**如实说「这一层量不到」**，不许当成「没有弹层」，也不许当成「被挡着」。
2. **影子宿主（shadow root）里的目标** —— 仓里已有先例（缺陷单 2026-10-12「选国家点不动-影子宿主」）。期望：探针走「穿好 shadow root 的那份元素表」，与表那套同一把尺子。
3. **探针 JS 被「裸 return」坑** —— blavity 那次「负向对照通过」是**假通过**（`cdp eval --file` 直跑裸 `return` = SyntaxError ⇒ 恒空）。期望：探针一律由 `_ev` 包成 `(function(){…})()`，且**合成页**能把它逮住。
4. **老产物不会自动获得** —— 能力进骨架只对**新生成**的生效。期望：文档/闸上说清，别让人以为 FMR 上那批也修好了。
5. **循环型没有 `when` 门** —— 它每一步现读页面 ⇒「关掉之后怎么算复核通过」的判据**不许**照抄固定步骤表那把（后者靠 `when` 门 + `prog`）。期望：复核 = **重新 read 一次**，那一格不再被挡。
6. **一整轮里页面被弹层换掉** —— 循环型每轮可能停在完全不同的屏上。期望：探针每轮都要跑（不是只在开跑前）。
7. **产物变大会不会撞字节上限 / FMR 那条写口** —— 表那套的骨架已含这几百行；循环型加完之后要量一次字节数与重渲耗时。

## 摸底结论（2026-10-16 逐字取回源码之后，**与 spec §3.3 的假设不同**）

循环型**不是「一个字节都没有」**，它自带一条**弱路**，缺的是「形状判据」那一层：

| | 循环型**已有** | 循环型**缺**（本刀要补） |
|---|---|---|
| 认弹层 | `READ_PAGE_JS` 的读取器回一个 `consent` 字段 → `run()` 里 `if page.get("consent"): clear_cookies()`；`COOKIE_TEXTS` 按**词**认 | **按形状认**（钩子表：盖满视口的同意弹层 / 同意条 / 盖住整页的模态）——Fides、`MuiDialog` 那两型**词表认不出** |
| 时机 | **每轮**开头一次（`run()` 里） | **每次动手之前**（弹层是加载完之后异步冒出来的，见 10-13 那条真事） |
| 遮挡 | ❌ 没有（`click()` 直接点） | 落点判据（`_cover_once` 那把尺子） |
| 挪位 | ❌ | `_recenter`（粘性页眉那型） |
| 关掉之后 | ❌ 不复核 | **再读一次**（循环型的复核=重读，不是 `when` 门） |
| 报文 | `_stop(step, action, why)` 两格都写 ✓ | 「被挡着 ≠ 没找到」那句 |

✅ **spec §3.3 那条假设不用验了**：循环型的动作本来就是「**打标记 → `cdp click [data-sf-pick="1"]`**」
（`click()` 里那段 JS 找 → `setAttribute('data-sf-pick','1')` → 点标记）。所以落点判据**不需要**
token→path→元素这条路 —— **先打标记、再量 `[data-sf-pick="1"]` 的落点**即可：
找用 JS、动作走 cdp，与它自己那条路**同一把尺子**。
⚠️ 但**仍要验一件事**（Task 1）：真浏览器里，**标记之后 `elementFromPoint` 能不能说清"盖着它的是谁"**
（尤其跨域子帧 / 闭 shadow）。
