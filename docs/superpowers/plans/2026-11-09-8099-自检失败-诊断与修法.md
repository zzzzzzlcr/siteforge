# 8099 自检失败诊断与修法 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 8099 的四类自检失败不再给出错误失败族、不再让软行顶掉真失败：① 浏览器错误页立即记成硬失败并归 `precondition`；② 注册页的隐私勾选框不再被同意条钩子认成弹层；③ 诊断的主证据与跨轮指纹只认硬失败；④ 生成侧合并无进度的重复步、清掉 CSS 文本锚与占位符判据。并把上述行为钉进离线测试。

**Architecture:** 不动生成脚本的整体形态，只补四处边界：① 产物运行时在**所有会导航的动作**落地后检查浏览器错误页（不只 `goto`）；② 前提层钩子不再把表单里的 checkbox/radio 当同意条；③ 诊断层从 trace 行算出 `hard_failure`，软行不进主 note、不进指纹；④ 生成侧只做去重、文本清洗与占位符拦截。生成侧不重写状态机，诊断层不改 `_diagnose` 的 draft 路由（见「已知边界」）。

**Tech Stack:** Python 3、pytest、`agent/template.py` 生成的产物骨架、`agent/selftest.py` 的 trace 判据、`agent/graph.py` 的失败族、Chrome DevTools Protocol 回执。

**Spec:** 无独立 spec 文件；证据、范围与代码位置见本文件「背景」与「证据基线」。执行者按本文件的任务与验收标准实施。

## 背景

8099 的 `runtime/checkpoints.sqlite` 里自 2026-10-26 起有 **39 个自测失败的 job checkpoint**，集中在：

- 导航错误页被当成“页面动过”：`chrome-error://chromewebdata/` 后仍 `progress=true`，后续 `when` 全跳过。
- 同意条钩子把注册页的 `I agree to the Privacy Policy` 勾选框当弹层，软失败顶掉真正的硬失败。
- 探索账本把连续无进度的 `Quick view` / `Add to cart` 原样重放，生成 3 个重复步。
- 目标文本里混入 CSS（`input{ -webkit-appearance:none; } ...`），状态判据里混入 `undefined`。
- 诊断的 `first_bad` 回退到软行，`failure_identity` 只拿到 `点名:同意条`，两轮后被判 `repair_stuck`。

## Global Constraints

- 不新增第三方依赖；只用标准库与仓库现有工具。
- 测试必须离线、确定性；不得访问真站、不得开真浏览器窗口。
- 不改生产站点行为；只改 `agent/` 与 `tests/`。
- 老 trace / 老 checkpoint 必须仍能读：新增键只能是可选的，旧键语义不变。
- 失败消息与注释保持仓库现有中文口吻；不写“大概 / 也许 / 适当处理”。
- 测试里的 `agent` 函数一律带模块前缀（`graph._failure_family` / `selftest._verdict` / `browser_agent._target_of` / `lint._judge_violations`）—— 现有测试就是这么写的；裸名字会 NameError。
- 每个任务只跑本任务相关测试；但每个任务的 Run 必须包含本任务会碰到的**现有**测试（下面各任务已列出），不要只跑新增用例。
- 真实 trace 若要进测试，必须先从 `runtime/` 导出成 `tests/fixtures/` 下的 JSONL；`runtime/` 不进 git，测试不得直接读它。

## Review Focus

- 浏览器错误页不能与真实 404 页混淆：真实 404 有正文，`chrome-error://` 没有；只认浏览器错误页 URL / 错误文案。
- 错误页检查要覆盖**所有会导航的动作**（goto / click / form），不能只覆盖 goto。
- 同意条钩子不能把真正的同意条一起放过：真实 cookie banner 必须仍返回可点控件；用例必须能真正走到守卫的每一个分支。
- 去重不能删掉合法的重复动作：只合并同一状态内同一目标、前一步 `progress=false` 的连续 `click`。
- `pending` trace 行不能污染现有下游：所有读 trace 的代码必须忽略 `pending` 行，只有超时兜底用它。
- URL 规范化不能改变正常 URL 的语义：只反复把 `%25` 换成 `%`，最多 3 轮，不碰普通 `%E2`。
- 诊断的硬/软来源必须来自 trace 行，不从 `note` 文字反推。

- [ ] **Step 3: 实现 `_browser_error_why` 并接入三处**

在 `agent/template.py` 的 `SKELETON` 字符串内新增模块级函数（`SKELETON` 是 `string.Template`，代码里不能出现 `$`）：

```python
#: (小写匹配用, 回给人的原文)
_BROWSER_ERROR_MARKERS = (("chrome-error://", "chrome-error://"),
                          ("net::err_", "net::ERR_"),
                          ("this site can't be reached", "This site can't be reached"))

def _browser_error_why(url: str, text: str = "") -> str:
    """URL / 正文命中浏览器错误页标记时返回命中标记，否则返回空串。"""
    hay = ("%s\n%s" % (url or "", text or "")).lower()
    return next((say for needle, say in _BROWSER_ERROR_MARKERS if needle in hay), "")
```

```python
def normalize_entry_url(url: str) -> str:
    """只把百分号的二次编码收回来：最多 3 轮 %25 -> %。"""
    out = str(url or "")
    for _ in range(3):
        if "%25" not in out:
            break
        out = out.replace("%25", "%")
    return out
```
