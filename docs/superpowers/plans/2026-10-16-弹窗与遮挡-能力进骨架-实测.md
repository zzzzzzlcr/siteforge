### 2.4 复核三态：量到哪一支、没量到哪一支

brief 要的判据是「探之前有 / 探之后没有 ⇒ True；本来就不在 ⇒ None；还有 ⇒ False」。
这一趟**只走到 `ok=false` 的「还在（没敢点）」那一支**（既不是「探之前有、探之后还有」那句、
也不是「本来就不在」那句）—— 因为这一站上**没有任何一条钩子点得下去**。

| 态 | 这次量到？ | 为什么 |
|---|---|---|
| 点完复核 ⇒ **True**（探之前有 / 探之后没有） | ✗ **没量到** | 没有任何钩子给出可点的地址 |
| **None**（本来就不在 / 探不动） | ✗ 没走到 | 探针**答了**（只是答了个点不了的东西） |
| **False**（还有） | ○ 走到近亲：`ok=false`「还在（没敢点）」 | 见 §2.2-① |

## 3. 字节与重渲耗时（Review Focus #7）

```bash

```

| 家族 | 旧（交付时那份） | 新（当前骨架重渲） | Δ | 重渲耗时（中位 / 范围） |
|---|---|---|---|---|
| 固定步骤表 `wildnutrition.py` | 268,321 B | 274,861 B | **+6,540 B**（+108 行 / −27 行） | **3 ms** [2–16] |

## 4. 代价量证

### 4.1 一把 eval 的两把尺子（§4-①）

**页内**是页面自己用 `performance.now()` 夹出来的；**端到端**是 `CDPHelper.eval` 那条路
（起进程 + websocket + eval）—— 两个数差 1~2 个数量级，「探针有多贵」只能看前者。

量在 **compareinsulation 那一页**（377×757，250 个元素；探针 5,481 字 / 5,617 字节 / 4 条钩子，每组 7 次）：

| 跑什么 | 端到端 中位 | 端到端 范围 | **页内 中位** | 页内 范围 |
|---|---|---|---|---|
| 产物自己的 `read()`（`READ_PAGE_JS`） | 0.046 s | 0.041–0.068 | **0.30 ms** | 0.20–0.40 |
| **探针** | 0.045 s | 0.042–0.064 | **2.30 ms** | 2.20–2.60 |
| 合一趟（read + 探针） | 0.056 s | 0.044–0.059 | **2.50 ms** | 2.00–5.20 |

**同一个探针在 wildnutrition 那一页**（5,532 个元素）：页内 **8.2–87.4 ms**、端到端 0.096–0.373 s。

⇒ 两条结论：
1. **端到端那一格量的是进程启动，不是探针**（read 与探针几乎一样贵 ≈ 45 ms）。挂「每一步动手之前」
   花掉的就是这一次**往返**，与钩子条数无关（探针是**拼成一段**的：第一个答应的就 return）。 见 `_popup_probe_js`。
2. **页内随 DOM 规模涨**：250 个元素 2.3 ms → 5,532 个元素 8~87 ms（同一段探针、两个站）。
   对照 Task 1（那趟探针 1,472 B、无钩子表）：同站 **0.4–1.0 ms**；本刀 5,481 字（5,617 B）⇒ **2.3 ms**。
3. **别拿它去对 blavity 那个 0.15~0.6 秒/步**（brief Step 3 的对照数）：那一个是**产物内部**调
   `CDPHelper.eval` 的读数，本节的端到端是**宿主侧 CLI 直量** —— 这条口径差记在
   **`docs/probes/2026-10-16-loop-cover/README.md` §二④**（「两边别互相引用」那句原文就在那儿），
   **不在** blavity 那份 README 里。

### 4.2 搭车：探针与每次 `read()` 能不能共用一趟（§4-②）

**成本上：能。** 合进一次 eval 之后，页内 2.30 → **2.50 ms**（几乎不涨：read 自己只 0.3 ms），
端到端 **0.056 s vs 分开两趟 ≈0.091 s** ⇒ **省一次往返 ≈ 35 ms/次**（7 次中位）。

**设计上：只有一处搭得上。** 探针有 4 个调用点（开跑前 / 前置之后 / **每一处动手之前**），
`read()` 是**每一轮一次**；而且 `clear_popups()` 自己是「探 → 点 → **再探复核**」三步，
**复核那一次永远搭不上**（它必须发生在点击之后）。
⇒ 「能不能」= 能（一句 `return` 的事）；「该不该」= **只省下与 read 重合的那一个调用点**，
本刀**没有改**（改它就是动骨架，本 Task 明令只读）。
