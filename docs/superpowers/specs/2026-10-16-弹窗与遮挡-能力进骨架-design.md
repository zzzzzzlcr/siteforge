## 1. 这件事治什么

### 1.1 一句话

「遇到弹窗/遮挡该怎么办」这套能力**只长在两套产物骨架中的一套里** —— 固定步骤表那一套
（`agent/template.py`）有，循环型那一套（`agent/template_loop.py` 的 `_LOOP_SKELETON`）
**一个字节都没有**；而循环型那族（单页漏斗 / 问卷）恰恰是弹层最多的一族。
所以「**让以后的脚本都有这个能力**」今天做不到 —— 走循环型的站拿到了半份能力。

### 1.2 量出来的（2026-10-16，逐条可复跑）

**① 两套骨架的差**（工作区计数）：

| | `_covered_by` | `_clear_obstructions` | `_POPUP_PROBE_JS` | `_POPUP_HOOKS` | `elementFromPoint` |
|---|---|---|---|---|---|
| `agent/template.py`（固定步骤表） | 20 | 10 | 3 | 7 | 5 |
| `agent/template_loop.py`（循环型） | **0** | **0** | **0** | **0** | **0** |

**② 池子里的产物**：12+ 份**真实循环型**产物（`chattyromance` / `foodandwine` /
`solarincentives` / `compareinsulation` / `goldenromances` …）`_covered_by` **全是 0**；
而固定步骤表那两份带着手工补丁（`kotzheating.py` 10 处，10-09 那刀）。

**③ 一条真事正好落在这半边**：`job-c02d5768e535`（compareinsulation）自测两轮都卡在
「Accept All Cookies」弹层 —— `_failure_family` 判成 `**overlay**` 族、两条诊断逐字相同、
图自己停（`repair_stuck`）。那个站就是**循环型**，`_covered_by 0`。

**④ 「已知可安全关的」今天住在两处**：

| 住哪 | 内容 | 代价 |
|---|---|---|
| **骨架**（`template.py`，新产物人人有） | 三条通用钩子：盖满视口的同意弹层 / 同意条 / **有模态语义**的模态框 | 加一行 = 以后都有 |
| **产物**（一站一补，推 FMR） | kotzheating 的 `div.op2-close`（10-09）、blavity 的 `data-click="close"`（10-10，`f34b3071`→`99991e4d`） | 每站一次；**重出即丢** |

两份产物补丁的判据**已经是同一族**（可见 + 有尺寸 + 中心点 `elementFromPoint` 落在它自己/
祖先/后代 + 关掉之后**再探一次复核**），差的只有「怎么认出那颗关闭键」。

### 1.3 共同形状

**能力写在骨架里 ⇒ 一处改、此后每一份产物自动带；写在产物里 ⇒ 每站一次、重出即丢。**
这一刀要断的就是后者。

## 2. 目标与非目标

**目标**
1. 循环型骨架补上那一套：遮挡判据（落点）、等待/挪位、钩子表、关掉之后复核、停与报文的纪律；
2. 两套骨架的**判据同源**（一份源、两处渲染；改一处必须改两处，用例两边都要有）；
3. 钩子表加一行「**广告 creative**」（判据已被 kotzheating / blavity 两份产物试出来）。

**非目标**
- **不做**「AI 判弹窗」「关掉一切浮层」：政策仍是「**已知安全的才点，认不出就什么都不做**」
  （2026-10-10 收窄是**故意的**：一般的浮层可能是页面自己要人看的东西）。
- **不追** FMR 上正在跑的老产物：能力进骨架只对**新生成**的生效（要老产物也有，得重出/重推，单列）。
- 不动布局、预算、修复轮数、步骤序列。
- 不动「探路/生成期怎么把站点那点知识记下来」那条链（见 §7-3）。

## 3. 设计

### 3.1 判据一套，两处用（同源，不靠 import）

产物是**自包含**的 .py（生产里单独跑，不能 import 本仓任何东西）⇒「同源」只能落在**渲染期**：

- 那段探针 JS 与那几个判据常量，抽成**模块级源字符串**（`_POPUP_PROBE_JS` 已经是这么来的，
  `template._popup_probe_js()` 在 import 期拼一次）——**两套骨架在渲的时候取同一份**；
- ✅ **已经核过：这条路是通的、而且是一行 import** —— `agent/template_loop.py:27`
  本来就在 `from agent.template import _json_lit, _lit, _provenance_literal`，
  而 `agent/template.py` **不** import `template_loop` ⇒ **没有环**（两套骨架之间的依赖是单向的）；
- 判据本体（可见 + 尺寸 ≥8×8 + 落点 `elementFromPoint` 是自己/祖先/后代 + 「找不到就什么都不做」）
  **一个字都不许各写一套**；两套骨架各自只需要**挂点**与**报文**（§3.2、§3.5）；
- 纪律：以后改判据 ⇒ **一次改源**，两套骨架的用例各跑一遍（§5.1 那条断言就是防漂的钉子）。

### 3.2 循环型那三个挂点（**新东西**：它的目标不是选择器）

循环型每一步现读页面、按快照里的 **token** 动手（`click(token)` / `fill(token, value)` /
`pick_option(options)`），所以：

1. **每轮之前 / 导航之后** —— 对应表那套的 `_clear_obstructions` 调用点；
2. **每次 `click` / `fill` / `pick_option` 之前** —— 对应表那套 `_perform` 里那一处
   （「弹层是加载完之后异步冒出来的」那条真事就是靠这个挂点治的）；
3. **动手之后** —— 复核（§3.4）。

### 3.3 token → 元素的落点判据

表那套的目标是选择器（`_covered_by(selector, frame_id)`）；循环型的目标是 token
（`walk(node, path, depth)` 出来的那棵树里的一格）⇒ 落点判据要**落到那个 token 对应的元素**上。

✅ **2026-10-16 晚订正（写完计划、逐字取回源码之后）**：**这一格不用走 token→path 了** ——
循环型的动作本来就是这个形状：**JS 找 → `setAttribute('data-sf-pick','1')` → `cdp click
'[data-sf-pick="1"]'`**（`fill` 那条是 `data-sf-fill`，`pick_option` 走同一套标记）。
所以落点判据**先打标记、再量 `[data-sf-pick="1"]` 的落点**即可 —— 找用 JS、动作走 cdp，
与它自己那条路**同一把尺子**，也不需要把 path 取回元素。
见 `docs/superpowers/plans/2026-10-16-弹窗与遮挡-能力进骨架.md` 的「摸底结论」那一节。
⚠️ **真浏览器上仍要验一次**（计划 Task 1）：标记之后 `elementFromPoint` 说得清「盖着它的是谁」吗
（尤其跨域子帧 / 闭 shadow）—— 验不通就只做钩子表，**落点判据记成做不到**、不许硬写。

⚠️ **量不到就如实说「量不到」**（跨域子帧 / 影子宿主 —— 10-09 那单的根因就在**跨站子帧**里，
`elementFromPoint` 在那层够不着）：**量不到 ≠ 没有弹层**，这一格必须漏出去让人看见。

### 3.4 「关掉之后」怎么算数

- 关掉那一下**走 cdp 的拟人手势**（规格 §5.2：手拼的只许是「是哪一个」这个判断）；
- 「cdp 回 ok」**不算做成** —— 要**再探一次**（那颗关闭键 / 那块遮罩还在不在；blavity 那条
  就是「点完再探一次复核」）；
- 循环型每一步现读页面 ⇒ 复核的判据是「**重新 read 一次**，那一格不再被挡」，
  **不许**照抄固定步骤表那把（它靠 `when` 门与 `prog` 判页面有没有动）。

### 3.5 停与报文：**不许静默跳过**

- 被挡着且认不出 ⇒ 那一步**如实失败**（循环型用它自己的 `_stop(step, action, why, **kw)`），
  报文点名「谁挡着」，并说清**等过 / 挪过**（与 `cover_why` 同一副骨架）；
- **不许**把「被挡着」写成「没找到」，**也不许**写成「做成了」——
  2026-09-18 gowizard 那趟就是 cdp 回 ok、被记成做成了；
- 钩子探针**自己永远不许变成新的失败点**（探不动 / 点不动只记一行 INFO，与 blavity 同口径）。

### 3.6 站点知识只能是数据

| 是什么 | 住哪 | 例子 |
|---|---|---|
| **能力**（判据 / 探针 / 等待 / 挪位 / 复核 / 报文） | **骨架**（一处） | `_POPUP_PROBE_JS`、钩子表 |
| **一型的知识**（「广告 creative 长这样」） | **钩子表里一行** | 关闭语义 = 属性 `data-*close*` / aria / 文字，任一命中 |
| **一站的知识**（那座桥只有这一站有） | **表里可配的一格 / 账本一行** | kotzheating 的 `div.op2-close`、blavity 的 `data-click="close"` |

⚠️ **一旦某站的东西写成骨架里的代码，就又回到「一站一补」** —— 这是本刀要断的那条路。

## 4. 数据形状与兼容

- 钩子表**加一行**「广告 creative」（次序 = 优先级，放在同意那三条**之后**：
  它比同意条硬，但比「盖满视口的同意弹层」软 —— 后者底下什么都点不到）；
- 循环型产物里新增的常量**与表那套同名**（`_POPUP_PROBE_JS` / 同名方法），便于两边对照与排查；
- 产物字节会变大（表那套的那几百行 + 探针）；判据「**渲一份最小产物，那几样都得在**」（§5.1）。

## 5. 验收条件 + 量证

### 5.1 一条断言（这就是「以后都有」的判据）

两套骨架**各渲一份最小产物** ⇒ `_covered_by`（或循环型的等价物）/ `_POPUP_PROBE_JS` /
钩子表**都得在**。这条钉子同时防「两套骨架再漂」。

### 5.2 合成页（各 4 条，与 blavity 那张矩阵同形）

隐藏重复件排在文档顺序前面 ⇒ 探针精确命中可见那个；点标记 ⇒ 点到的是对的那个；
点完再探 ⇒ 空；**可见但被盖住** ⇒ 探针返空、**不点**。

### 5.3 真站验收（工具侧，各一趟）

- 固定步骤表：一个真站（对照：kotzheating / blavity 两例的判据仍然成立）；
- 循环型：拿 compareinsulation 那类站（**靶子是 §1.2-③ 那条真事**：同意弹层挡住填写框 ⇒
  循环型要能关掉它、并如实复核）。

### 5.4 代价（每步 +1 次 eval）

blavity 实测 **0.15~0.6 秒/步**（对照门铃 `_DOORBELL_JS` 0.14 秒）。循环型要**另量**
（它每步本来就 read 一次，探针能不能搭那次 read 的车 —— 量了再定）。
