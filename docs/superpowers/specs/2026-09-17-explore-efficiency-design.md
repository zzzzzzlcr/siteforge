> **为什么有这一片**：一次真站验收跑下来，人的结论是——**产出效率好差**。
> 生成这条路，慢到不值得走。于是排期改了：**先解决这两件，再做界面**（R-41 的「最小可视」往后挪）。

## 零、先把话说准

### 0.1 实测证据（人给的，按事实读，不当传闻）

| # | 事实 | 出处 |
|---|---|---|
| E1 | Bit 窗口**自己死**，约 **8 分钟**一次；一次实测寿命 **7m42s** | `closeTime 17:13:30` − `operTime 17:05:48`（worker 自己的 `/browser/detail` 记录） |

| E5 | 人眼看着它走到「填你的姓名」那一步，然后**从零开始重来** | 这就是 `reopen` 的现状：`agent/service.py:91` `WINDOW_STEPS = {"explore": "intake"}`，**接在 intake 上 = 探路整个重跑** |
| E6 | **生产重放不受影响**：产出的 py 驱动同一条 33 步表单，**1~3 分钟**跑完，稳在窗口寿命之内 | 所以问题**只在生成侧** |

### 0.2 成本模型那句话要改一个字

规格十三的原话是「**生成贵，可接受**；重跑必须便宜」。这句话今天**不成立**了 ——
不是「贵」的问题，是**贵到没有上界**：窗口每 8 分钟死一次，而死一次就得把整段探路连同
已花的模型轮数一起扔掉。于是花的钱与「探到多少」**不成正比**，跑多久都不保证收敛。

**本设计要的不是「便宜」，是「有上界」**：

```
今天：(模型轮数) × (窗口重启次数) —— 无上界
本设计：(一次探路的模型轮数) + (重放：0 模型轮数) × (窗口重启次数)
```

⚠️ 这条不推翻 P5（「预算的目的是防跑飞，不是省钱」）。**恰恰相反**：
`max_rounds` / `max_steps` 今天**是错的单位** —— 它是「每次尝试」的上限，
跨尝试不累计，于是「防跑飞」这根线在窗口反复死的时候**根本不响**。见 §1.8。

### 0.3 这一片**不**做什么

- **不动生产重放路径**（`forms/`、`common.py`、产出的 py 一个字节都不改）
- **不碰 `tools/cdp`（Go 侧）** —— 工具清单不变，`observe` 不加参数、不加字段（§2.4）
- **不做界面**（R-41 的最小可视是下一片；本设计只保证它要的数据在账上）
- **不做「人纠正一句、原地接着探」**（见 §2.6：那是 Console 那一片的事）
- **不做元素框选 / patch 预览 / 记忆层**（R-41 的范围界定，与本片无关）
- **不做模板层**（见下 §0.4 —— 有主，且是**另一个问题**）

### 0.4 明写的非目标：**产物表达不了「通用步进循环」**（有主的缺口，不是本片的任务）

生产里那个「聪明的脚本」是 `forms/sites/blinkist.py`（**374 行**，在
`/opt/skills/auto-farm-skill/`，不在本仓库）。它自己的头注释写着它为什么聪明：

> 设计要点（可靠性优先）：**通用步进循环：不硬编码步骤清单，每轮按 DOM 判断该做什么
> （防 A/B 变体 / 步骤增减）**……每步以 URL 变化为推进判据，超时重试。

而 siteforge 的产物骨架（`agent/template.py`）能表达的只有
**「一串状态 + 每个状态里固定几步」**，动作集合是 `click / form / scroll / goto / wait`
（`REPLAY_ACTIONS`，`agent/browser_agent.py:85`）—— **没有循环、没有「每轮重新判断」**。

**所以：今天这张模板表达不出 blinkist.py 之所以好的那个东西。**

- 这是**模板层**的问题（§5.1 产物契约那条线），**不是探索效率的问题**
- **owner：模板层那一片**（§5.1 的后续 / 计划五）。本片**不碰** `template.py` 的骨架
- 写下来是为了拦住一句会自然发生的误读：
  **「探索可续 + 描述当计划」做完 ≠ 「能产出 blinkist.py 那种脚本」。**
  本片能保证的是**探得稳、探得快**；产物能表达多少，**仍是模板层的事**（§四 C5 那条判据钉着这句话）

## 一、问题 A：探索可续

### 1.1 现状：死一个窗口，代价是什么（读代码得到的，不是推测）

窗口在探路途中死掉，代码里会走成**三种形状**，**每一种都丢东西**：

| 形状 | 怎么发生的 | 丢什么 |
|---|---|---|
| ① **磨到预算** | 窗口没了以后，每次 `call_tool` 都抛 → `dispatch` 的 `except Exception`（`agent/browser_agent.py:272`）把它**记成那一步的失败** → 还给 `run_tool_loop`，模型继续试。**模型看不见「窗口没了」，只看见「这一步没成」** | 剩下的全部轮数，全花在一个死窗口上 |
| ② **停在 `explore_unfinished`** | 循环走到头（`_wrap_up`，`:359`）→ `FINISHED_EXPLORATION` 只认 `model_done`（`agent/state.py:114`）→ `_explore` 判 `END_EXPLORE_UNFINISHED`（`agent/graph.py:348`） | 账本**存进了** checkpoint，但 `reopen` 只会**从头再探**（`WINDOW_STEPS`） |
| ③ **整个 job `failed`** | `deps.explore` 抛穿透（`_advance` 的 `except BaseException`，`agent/service.py:603`）→ `_resume_point` 走 FAILED 那一支 | 一样，探路从头来（`agent/service.py:904`） |

**三种形状的共同点**：`journey.steps` 里**已经记下的那些步**，要么在内存里随进程丢掉，
要么进了 checkpoint 但**没人拿它做任何事**。**知识已经在了，是没人用。**

### 1.2 断点该放在哪：三个候选，各自的代价

| 候选 | 形状 | 代价 | 裁定 |
|---|---|---|---|
| **① 更细的图节点**（一轮模型 = 一个节点） | `NODES` 加 `explore_step`，每轮存一次 | ①**不解决根本问题**：新窗口是**空白**的（§1.5），页面位置**必须重走一遍**才回得去 —— 细节点只省「模型轮数」，回不去那一页照样回不去；②人那道闸（`_enter`，`agent/graph.py:228`）会从「一次探路问一次」变成**几十次**，Console 的「一轮 = 一道闸」整个模型要重做（`docs/superpowers/plans/2026-09-17-console-minimal.md` Task 4 的配对规则）；③`WINDOW_STEPS` / `_resume_point` / `visits` 全要改；④checkpoint 写入 × 轮数 | **不采纳** |
| **② 只在进程里存**（全局 dict / 内存） | 服务重启即丢 | 与 R-19（状态住在 saver 里）直接冲突 | **不采纳** |
| **③ 账本落盘 + 重放前缀**（**选定**） | 每一步**发生的那一刻**追加一行到磁盘；窗口死了 → 开新窗口 → **确定性重放**安全前缀 → 从落地页继续探 | 多一条持久化路径（与 R-19 的张力见 §1.3）；重放要一套自己的解析（比产物弱，见 §1.4.4） | **选定** |

**为什么 ③ 对**：它把「位置」这件事**用最便宜的方式重建** ——
重放 = 真浏览器动作 + **0 次模型调用**（人话原话：「they are cheap」）。
而 ① 花了 4 项成本，买到的只是「模型轮数按轮存」，**位置还是回不去**。

### 1.3 选定形状：账本落盘（journal）+ 重放前缀 + 一个闸

```
                        ┌──────────────── 一次 attempt ────────────────┐
窗口开 ──► [重放安全前缀] ──► [模型继续探] ──► 每一步 → journal.jsonl（追加）
   ▲              │                    │
   │        0 次模型调用           正常 ReAct（§探路）
   │              │                    │
   └── 窗口死了 ──┴────────────────────┘
        reopen → 读最新 attempt 的 journal → 重放 → 接着探
```

**四件东西**（都是缺的能力 → 都是任务，不是假设）：

| # | 东西 | 落在哪 | 为什么在这 |
|---|---|---|---|
| 1 | **`journal.jsonl`** —— 每步一行，**发生的那一刻**追加 | `runtime/explore/<job_id>/attempt-<n>.jsonl`（`runtime/` 不进 git，与 `runtime/selftest/` 同层不同目录） | 服务是**知道 job 与窗口的那一层**；`browser_agent.explore` 已经有 `on_step` 回调（`agent/browser_agent.py:230`），服务今天**没接**（`_explore_for`，`agent/service.py:488`）→ 接线即可，**不改图** |
| 2 | **`replayable_prefix()`** —— 纯函数：`(steps, success_text) -> (前缀, 边界理由)` | `agent/browser_agent.py`（与 `_replay_step` 同处） | 纯函数 = 可穷举单测，不用浏览器 |
| 3 | **`replay()`** —— 走前缀（MCP 调用，**0 模型**） | `agent/browser_agent.py` | 它已经独占「怎么开窗口、怎么 `_Pages` 记页、怎么 `when_holds`」这套知识 |
| 4 | **`explore(..., resume_from=…)`** | `agent/browser_agent.py` | 让**第二次进 `explore` 节点**这件既有的事实（`WINDOW_STEPS`）变成「接着走」而不是「从头走」 |

**图一个节点都不加、`NODES` 一个字不改。** 省下的正好是 ① 的全部代价。

**与 R-19（状态住在 saver 里）的张力，明说**：journal **不是状态**。
它是**一次失败尝试的账本**（证据），唯一真源仍然是 checkpoint 里的 `journey`。
两者的关系是**单向**的：journal → 喂给下一趟重放；`journey` → 产物。
**不许**有任何地方从 journal 读「这次探到哪了」这个判断（那是 `journey` 的事）。
判据写死：**把 journal 删掉，图必须照常跑完**（只是窗口一死就得从头来）——
这条要有一条测试钉住。

### 1.4 重放的可逆性分析（这一节是重点，不许含糊）

#### 1.4.1 先把「为什么必须有个边界」说清楚

重放是**把已经做过的事再做一遍**。做第二遍**不等于**第一遍：
第一遍是**人让它做的**（描述里写着 / 人在闸口点了继续），第二遍是**系统自己做的**，
**没有任何人要求过**。一件真实世界里有效果的动作，第二遍就是**一次没人要的重复**。

> 这个项目里**已经有**重复提交：扰动自测把整条表单跑最多 5 遍（§10），
> 用的还是随机数据。**但那是有人要的** —— 它就是在验「重跑跑得住」，重复是它的目的。
> **重放的重复不在这个豁免里**：它不在任何人的计划里，而且用的是**同一份数据**
> （journal 里记的就是上次填的那个值）—— 同一份数据的第二次提交，比一次新的提交更坏。

#### 1.4.2 判据只能从**账本已有的事实**里来（不许发明语义）

「这个按钮是不是提交键」是**判断**。往工具层塞判断正是 D11 逃出来的坑
（`tools/cdp/internal/mcp/registry.go:319` 的 `observe` 描述里写着：
「**不给判断** ——『哪个是主 CTA』这类语义要你自己从这些原始信号推」）。
所以重放的边界**不许**由「识别哪些词像提交」这种规则来定。

**能用的只有三样，都在账上**：

1. **`success_text`** —— 人给的成功判据（§6.1：这一条只有人知道，`intake` 缺它就停，
   `agent/state.py:99`）。**这是人的判断，不是我们的判断** —— 拿它做闸门是合法的。
2. **「这一步有没有被看见」** —— 账本里这一步**之后**有没有 `observe`/`diff`/`screenshot`。
   被看过 = 我们知道它把页面带到了哪；**没被看过 = 我们不知道它干了什么**
   （窗口就在这段里死的，正是 `operTime`→`closeTime` 那一段）。
3. **`journey.pages[].url`** —— 这个 attempt **亲眼见过**的页面地址清单。

#### 1.4.3 边界规则（写死，逐条可单测）

**一步可重放 ⇔ 下面四条全真**：

| 条 | 判据 | 为什么 |
|---|---|---|
| **R1 做成了** | `result.ok is True`（与 `_replay_step` 同一条，`agent/browser_agent.py:658`） | 没做成的动作重放它干嘛 |
| **R2 被看见了** | 这一步**之后**至少还有一条 `observe`／`diff`（即：**不是尾部那一段没被观测的动作**） | 尾部那一段是**最危险的一段** —— 提交几乎总是最后一个动作，而它后面通常没有 observe（模型走完就说完了）。**"没被看见的动作，一律不重放"** 是这条规则的全部力量所在 |
| **R3 没跨过成功线** | 到这一步为止（含它所到的那一页）观测到的页面文字里，**没有**含 `success_text` | 成功文案出现 = **这一趟已经成了**。**过了那条线之后的每一个动作都可能是重复的真实请求**。用的是**人给的判据**，不是我们猜的 |
| **R4 goto 只回自己去过的地方** | `goto` 的目标 URL（或其落地 URL）∈ `journey.pages[].url`，**或者**是入口 URL（载荷 `entry_url` / `state["url"]`） | 深链可能是**一次性**的（确认链接、令牌链接）。只重放「我们亲眼见过它是普通页面的地址」 |

**前缀的取法**：从头往后吃，遇到第一个不满足的步就**停在那儿**（不是跳过它继续往后吃 ——
跳过会得到一个「中间少了一节」的路径，重放它会走到别的页面上去）。
返回的还有 **`boundary_reason`**：一句**人话**，说清「为什么停在这」（R2/R3/R4 哪一条）。

#### 1.4.4 重放**不是**产物的重放机（两者强弱不同，明说）

产物的重放（`agent/template.py` 的骨架）有三跳：选择器候选 → 逐级失败 → **重新 observe
按 text + role + near 重定位**（§5.1b）。**这套东西长在产出的 py 里，agent 侧没有。**
MCP 的 `click`/`form`/`scroll` 只收一个**裸 CSS 选择器**
（`tools/cdp/internal/mcp/registry.go:369/380/392`）。

所以 agent 侧的重放**只能**：按 `target.selectors` 逐个试（`_selectors_of` 给的那份：
`element.selector` → `alternates` → 模型当时给的那个），**第一个能解析出来的胜**。

→ **重放的分辨力比产物弱**，这是**已知且可接受**的：
重放的目标只是「回到那一页」，不是「在生产里跑一万次」。
弱的后果由下面三条兜住：**逐页核验**（§1.6）、**失败就停**（§1.6）、**不可逆的一律不碰**（§1.4.3）。

⚠️ **`frame_id` 没记进账本**（`_summarize` 只从 args 抄了 `selector`，`agent/browser_agent.py:613`）
→ **跨源 iframe 里的元素今天重放不了**。这是**缺的能力**，写成 Task 5 的一步，**不许当它存在**。
（猜测：验收站是非 shadow / 非 iframe 站，这一条今天不挡路；**定它的办法**：看账本里
`target.near` 与 `observe` 返回的 `frame_path` 是否出现过 `main` 以外的值。）

#### 1.4.5 不可逆边界**之后**发生什么（三步，都是既有机制）

1. **重放停在边界前一步**，落地页 = 前缀最后一步所在的那一页。
2. **核实**：`observe` 一次，拿 `when_holds`（`agent/browser_agent.py:192`，与产物的
   `_applies` 同源）比对**前缀最后那个状态的 `when`**。**不成立就停**（§1.6）。
3. **把控制权交回**：`explore` 节点门口那道闸（`_enter`，`agent/graph.py:334`）
   的 `facts` 里带上**重放摘要**（重放了几步 / 停在哪一步 / **为什么停**：哪一条 R 判的）。
   人在这儿**看得见、拦得住、指得了路**（§6.2）。
   紧接着模型拿到**续跑简报**（§1.7），从这一页接着探。

**注意顺序**：重放**在闸之后**发生（闸在节点开工前，`_enter` 是节点第一件事）——
但闸上要说的那份摘要**不需要重放就能算出来**（它只依赖 journal），所以闸上说得出来。
「重放本身会不会出副作用」这件事，由 §1.4.3 保证：**它里面就没有不可逆的动作**。

### 1.5 站点自己的状态能不能跨窗口活着（**不能**，这决定了重放是「重走」不是「续接」）

`skills/bit-window/SKILL.md` 的权威 JSON 里写死了两条：

```jsonc
"clearCacheFilesBeforeLaunch": true, "clearCookiesBeforeLaunch": true,
"browserFingerPrint": { "coreVersion": "<random 130|132|...>", ... }
```

→ **新开的窗口是一个干净身份的浏览器**：没有 cookie、没有 localStorage、**指纹都不一样**。

推论（**这一条改变了重放的形状**）：

- **服务端会话（挂在 cookie 上）没了** → 任何「只活在会话里的漏斗进度」都没了
- 所以重放**不能**理解为「在那一页接着做」；它只能是「**从入口重走一遍**」
- 因此：**重放的第一件事必须是 `goto` 入口**（journal 头上没有 `goto` 时，
  由 `state["entry_url"]` / `state["url"]` **合成**一条）
- 该站把进度放在 **URL** 里的话（query / 路径段），重走会**直接落到中间那一步** ——
  这正是 R4 允许的（那个 URL 是「见过的页面」）

⚠️ **猜测（没量过）**：同一台 worker、同一条 gost 链（同出口 IP）、**不同指纹**，
连着走两遍同一条路径，站方会不会拦（验证码 / 风控 / 就是那个取消弹窗）。
**定它的办法**：Task 1 的窗口时间线里，把重放那一段单独标出来，
记「这一段有没有出验证码 / 拦截 / 意外弹窗」；Task 7 的验收跑里对照。

### 1.6 重放失败怎么办（**一律停下说话，不许静默跳过**）

三种失败，三种处置，**都不许"跳过这一步接着走"**：

| 失败 | 判据 | 处置 |
|---|---|---|
| **元素解析不出来** | `target.selectors` 全试完都没找到 | 重放**停在这一步前**，`boundary_reason` 说清「页面上找不到『开始申请』那个按钮了」 |
| **落地页不是那一页** | 走出这一步后 `observe`，与前缀里**该步之后那个状态的 `when`** 比，`when_holds` 为假 | 一样停；理由带上「我以为会到 X，实际是 Y」 |
| **窗口又死了** | 重放途中 `call_tool` 连失两次（见 §1.8） | 重放**整段重来**（它里面没有不可逆动作，重来是安全的）—— **最多 3 次**，到顶就停并说明 |

> ⚠️ 为什么这么严：**"静默跳过"正是 R-35 那次失败的形状** —— 一条不成立的 `when`
> 让 7 步被静默跳过，报告却什么都看不出来（`17e5aa4` 修的）。探路侧不许再犯一次。

第 2 条是**逐页核验**：不是每一步都核，只在**账本记着「这一步改了页」的那些点**核
（判据：这一步之后那条 observe 让状态名变了）。一页一次 observe，**0 模型调用**，很便宜。

⚠️ **分支站的推论（§2.2）：核验失败 ≠ 站点坏了 —— 也可能这一趟落到了另一条分支上。**
重放把**同一串动作**再走一遍，而分支站的同一串动作**通常**落回同一个分支
（填的值是重放里原样带的，选择因此是确定的），但**不保证**（站方 A/B、轮换变体）。
系统**分不出**「选错了元素」与「落到另一条分支」——**两条都停**。
代价说清：停 = 叫一次人；不停 = 在一次没人看着的重放里继续点真页面。**选停。**
（核验用的判据必须是**产物那套放宽后的 `when`**（R-37 的稳定前缀 + 文本），
**不是逐字节比对** —— 后者会把「同一页的轮换变体」误判成失败。）

### 1.7 续跑简报给模型什么（以及**不给**什么）

**给**：已重放的步（一句话一步，`note` 字段就是现成的人话）、当前在哪一页、
**下一个被记下的动作是什么**（以及它为什么没被重放 —— 那是模型最需要知道的边界信息）。

**不给**：重放那些步的**原始工具返回**。理由有两条，都硬：
① 目标是**省模型轮数**，把 30 步的原始返回塞回去等于又付一遍上下文钱；
② 重放里可能有**不该让模型当成"我做过"**的动作 —— 明说是「重放」，模型才会在
需要时重新确认（`_SYSTEM` 第 3 条：click 返回 ok 只代表命令下发了）。

### 1.8 预算该换个单位（连带修好的一处**真**漏洞）

今天 `Caps.explore_steps` / `explore_rounds`（`agent/state.py:138`）是**每次尝试**的上限。
窗口反复死的时候，**每次重试都给一份新预算** → 「防跑飞」那根线**根本不响**。
→ 本设计把上限挪到 **job 级累计**：`state["explore_spent"] = {steps, rounds, attempts}`，
每个 attempt 往里加，`Caps` 判的是**总数**。重放的步**不计入** `steps`（它不花模型的钱），
但要计入 `attempts`（它有真动作、有代价）。

**窗口死掉要成为一个一等停因**（今天不是）：注入 `Deps.window_alive`（服务侧现成：
`BitWindow.alive()`，`agent/service.py:183`）。工具连续失败 2 次时问一次它，
`False` → `_Stop("window_gone")` → 节点以 **`END_WINDOW_GONE`** 收尾（**新常量**）。
**不许**去正则匹配工具的错误文字（「连不上 host:port」），
那是**猜文本**；`alive()` 是**问接口**。两件事的可靠性差一个量级。

**为什么必须有这个区分**：`reopen` 的处置**依赖它** ——
「窗口死了」→ 该续跑（账本在）；「模型把预算走完了」→ 续跑只是**再烧一次**，
该让人看。今天两者都落在 `explore_unfinished` 里，**分不开**（`agent/service.py:95`）。

### 1.9 与 P6 / R-40 的关系（不新开一条路）

`reopen` 那条支路**已经存在**（`agent/service.py:823`），本设计**不换它**，只换**它接上之后跑什么**：

| 今天 | 本设计 |
|---|---|
| `reopen` → 探路**从 intake 重跑**（人话写在 `:878`：「探路要从头再走一遍」） | `reopen` → 探路**从 journal 重放**，接着走（那句话要改） |
| `END_PAUSED` **接不住**（不在 `WINDOW_END_REASONS["explore"]` 里，`:95`） | 一并接住（人喊停之后，账本没丢，重开窗口就能接着走）—— Console 设计注 §八 抱怨的就是这条 |

## 二、问题 B：描述当计划

### 2.1 现状：描述今天是怎么进 prompt 的（一个字都没多）

```python
# agent/browser_agent.py:827
def _brief(url: str, goal: str, plan: Budget) -> str:
    return (f"目标站点：{url}\n要做的事：{goal}\n"
            f"（你最多走 {plan.max_steps} 步、{plan.max_rounds} 轮。"
            f"现在这个浏览器窗口可能停在别的页上，先确认自己在哪。\n"
            f"⚠️ **能回答了就直接停下来说**…）")
```

**那 33 步，和散文一起塞在「要做的事：」后面。** 系统的行为是**自由探索**
（`_SYSTEM` 六条规矩里，一条都没提「照着人给的步骤走」）。
于是模型**把描述里已有的东西，靠看页面重新发现一遍** —— 这就是轮数多的直接原因。

**而且它会乱点**：规格 §1.1 的原始论点就是「页面能告诉 agent **机制**，只有人能告诉它**意图**」。
不知道「哪条路是业务要的」的模型只能试 —— 试就试进了站点自己的取消弹窗（本次实测）。

### 2.2 选定形状：**计划模式**（描述 → **检查点清单** → 一步一确认）

#### 先说一个前提：描述里的「33 步」是**一条走法**的长度，**不是站点的结构**

> 人 2026-09-17 原话：「33 步也并不一定确认啊，有些选错了可能就是 34，也可能 20 步都不一定
> —— **大部分问卷类都这样**。」

问卷 / 评测 / 投保这类漏斗是**分支**的：选了 A 多出三道题，选了 B 直接跳过它们。
**同一条描述，两个分支跑出不同的步数是正常的、必然的**（32 / 34 / 20 都合法）。

**这一条决定了整套东西的形状**（它不是一个边角情形，是这类站点的常态）：

- 计划是**检查点清单**（「应该到这儿」），**不是脚本**（「第 3 步点 X、第 4 步点 Y」）
- **走到某个检查点要几个动作、这条路上到底有几个检查点，都是「这一趟」的事**
- 所以：**步数变长或变短，本身不构成偏离**。只有「页面与描述矛盾」才构成（§2.3）
- 所以：**不许**把「33」这个数字写进任何判据、断言、上限或产物

⚠️ 这条对**产物**的含义见 §2.3.2：产物的 `when` **本来就是为分支设计的**
（`_when_for` / `_stable_url` / R-35→R-37 那次修的就是它），本片**不许**削弱它。

```
描述（人写的 prose）
   │  plan.parse()   ← 纯函数，零模型，只认「编号行」，一个字都不改写
   ▼
Plan{steps: [{n, text}, ...]}   source = "goal" | "evidence" | ""（散文）
   │
   ├─ 有步骤（≥2）→ **计划模式**：简报里是清单；模型逐步走；每步核验；停滞就停
   └─ 没步骤      → **自由模式**：与今天**逐字一致**，且在说法里明说「没给步骤清单」
```

**这一条是本设计的核心取舍：解析**不交给模型**。**
理由：模型解析 = 又要一轮模型调用 + 每次解析都不一样（同样的描述两次跑出不同的计划，
那「快了多少」就永远不可比）。**编号行是确定性的**，33 步那张描述就是编号的。

**「一个字都不改写」是硬规矩**：不改写、不摘要、不合并、不重排、不补全。
模型看到的必须是**运营的原话** —— 改写就是**替人重写意图**，而这个项目栽过的
「自信地错」正是这一类（§6.2 那张表）。

**而且：编号行抽出来的清单，不能把非编号行吞掉。** 真描述的格式是
**「键值头 + 编号清单」**，头里夹着**约束**（实测两份，都在 `fixtures/descriptions/`）：

```
（blinkist）  页面URL: … / 成功条件: Subscribe to Blinkist Pro / 成功条件URL: /news-feed,/welcome
              答题方式: 记录 / 意图: … / 引导: 1.滚动到底部 2.点击Featured Titles …
              禁止点击: Cookie Policy,Privacy Policy,Terms / 轮次: 30 / 浏览: 2
（homebuddy）  页面URL: … / 成功条件: Thank you / 操作: 1.填 Enter ZIP Code … 33.点 submit my request
```

→ **简报里给的是「原文 + 从原文里抽出来的清单」两样**（`Plan.raw` 就是原文）。
「`禁止点击: Cookie Policy,Privacy Policy,Terms`」这种**约束**如果被吞掉，
模型就会去点它 —— 而那是**运营明写的禁区**，不是废话。

### 2.3 描述含糊 / **绕开** / 矛盾 / 没有（四种情形，各有明确处置）

⚠️ 这里把「这一趟没走到某一步」与「页面与描述矛盾」**拆成两件** ——
它们在**原因、后果、要不要人看**三处都不一样（§2.3.1）。

| 情形 | 判据（机器怎么知道） | 行为 |
|---|---|---|
| **没有**（散文 / 一句话目标） | `parse()` 出 0~1 步 | **自由模式**（今天的行为），`explore_say` 里**明说**「这次没给步骤清单，是按目标自由探的」。**不许**假装有计划 |
| **含糊**（有步骤，但不是动作，如「走到报价页」） | 解析不出动作？**不判**（不解析语义） | 把每一步当**检查点**（「应该到这儿」），不当**脚本**。走到那一步要几个动作是模型的事；**位置只由模型报**（§2.4）。**不因此降级成自由模式** |
| **(a) 绕开** —— 这一趟**没走到**某个检查点（走了别的分支） | **位置标记往前跳**（§2.4：报了 `【第 5 步】`，而第 3、4 步没被报过）→ 被跳过的那些标 `jumped_over` | **正常，不算偏离**：**不进 `deviations`**、不触发停滞、不影响位置。人话里只当**事实**记着（「这一趟从第 2 步跳到了第 5 步」） |
| **(b) 矛盾** —— 页面与描述**对不上** | **模型报的**（一句声明，见下） | 模型**必须说出来**，且**只说它看见什么**：`【第 k 步】描述说点『有没有浴缸』，这一页上没有这句话，页面上是『屋顶类型』` → 记进 `journey.deviations`，**位置标记停在这一步不前进**。走完在 `explore_say` 里汇总：「描述里第 3、7 步与页面不符」 |

**(b) 的声明是「事实报告」，不是**分类**：** 模型**不许**去判「这是分支还是描述写错了」
（它判不了，也不该判）。**它报告「描述这句话 vs 页面这句话」，定性归账本和人。**

#### 2.3.1 为什么这两件必须分开（而不是都丢进 `deviations`）

| | (a) 绕开（分支） | (b) 矛盾（描述与页面对不上） |
|---|---|---|
| **多久发生一次** | 分支站的**几乎每一趟**都会发生（这正是人指出的事实） | 少见 |
| **要不要人看** | **不用** —— 它是站点本来的形状 | **要** —— 是描述这条信息本身的问题 |
| **怎么处置** | 什么都不做（检查点保持 `jumped_over`） | 人回看描述，或说一句纠正 |
| **放一起会怎样** | `deviations` 会被**日常噪音**灌满 → §6.3 那条「**同一处反复偏离**」的信号**彻底失效**（信号被噪声淹没，比没有信号更坏），人在闸口也会开始无视它 | —— |

**所以：`deviations` 里只装 (b)。** 这条是硬规矩，要有负例测试钉住
（造一条「模型从第 2 步跳到第 5 步」的桩 → `deviations` **必须为空**）。

⚠️ 顺带把命名说清：那个终态叫 **`jumped_over`（跳过去了）而不是 `skipped_by_branch`（分支跳的）** ——
**名的是事实，不是原因**。系统判不出「这是分支还是它漏做了一步」，**也不去判**；
它只如实记「从第 2 步到了第 5 步」，**怎么看由人**（账本上连页面状态序列一起给）。

#### 2.3.2 产物必须活下来的东西：**分支不许被钉死**

产物的 `states` 已经是**按页分组 + 每页一个 `when`**（`agent/browser_agent.py:148` 的 `states()`），
而 `when` 的存在理由**原话就是**「防 A/B 变体、**防步骤增减**」（`agent/template.py` / R-35→R-37）。
也就是说：**产物本来就是为分支站设计的**，本片**不许**破坏它。三条：

1. **检查点清单不进产物。** `plan_ledger` 是**给人看的账**，不是产物的原料 ——
   **`template.render()` 的签名与 `STATES` 的形状一个字节都不变**（要有断言）。
   ⚠️ 「第 k 步」这个概念**绝不许**出现在产出的 py 里：那等于把分支站钉死在一条路上，
   而这条路只是**这一趟**走的。
2. **产物是「这一趟走通的那条路」，不是「整个站点」。** 另一条分支的页面**不在**产物里 ——
   生产重放跑到那条分支上时，`_applies` 不命中就**整组跳过**（现成行为，不改）。
   这是**已知且接受**的边界（探索只走了一条路），**要写在 `explore_say` 里给人看见**，
   不新增字段、不放进 `PROVENANCE`。
3. **探索时走了哪条分支，产物里就是哪条分支的 `states`** —— 所以**别去"补全"另一条路**
   （那要重探一遍另一条分支，是另一件事，不在本片）。


**「fix」入口今天没有描述**（`RunRequest.evidence`，`agent/service.py:396`）——
它拿的是**失败证据**（formLog / formStep）。处置：

- **能做的**：`plan.parse()` 收 `evidence` 的文本。formStep 那类证据**本来就是带步骤序号的**，
  解析出来的就是「上次卡在第 N 步」的清单。**同一套机制，不另开一条路。**
- **今天做不到的（缺的能力，写成任务）**：规格 §6.1 说修站应当**以旧 py 的行走路线为起点**
  （「探路必须以旧路线为起点，而不是白纸探索」）。今天**没有任何地方能读到旧 py**
  （`RunRequest` 里没有这个字段，服务也不读 `forms/sites/`）。
  → **这写成 Task 2 的一个可选口子（`plan.from_states()`，读旧 py 的 `STATES`）**，
  不在这一片强制；**在它落地之前，fix 入口就是「证据文本 → 计划，或自由模式」**，
  设计注**不假装**它已经能读旧 py。

### 2.4 位置由谁报 —— 与「observe 只给感知」的关系（**这是本节的要害**）

D11 / 规格 §4.2 写死：**`observe` 给感知不给判断**；`registry.go:319` 的 observe 描述原话
「『哪个是主 CTA』『这一步该点哪里』这类语义要你自己从这些原始信号推」。

**所以系统不许去判「这一步完成了吗」。** 系统的位置标记只认两样：

1. **模型自己报的**：每轮开头 `【第 k 步】`（一个**约定**，不是新工具）。
   这是**声明**，不是判断 —— 系统只做**记账**（这一轮它说自己在第几步）。
2. **页面变了没有**：`_Pages` 已有的状态切换（`agent/browser_agent.py:703`）——
   **感知**，机械可判，而且是现成的。

**模型没报 / 报了个不存在的号** → 位置标记**不动**，`notes` 里记一句
「这一轮没说自己在第几步」（**如实记"不知道"，不猜**）。

**往前跳几号是正常的**（§2.2 的分支）：标记从 2 跳到 5 → 3、4 记 `jumped_over`，
**照样算「前进了」**（停滞判据因此清零）。跳过去的那几个**只是记账**，不是偏离（§2.3.1）。

⚠️ **往回跳也一样照记**（页面确实退回上一步时会发生），**不判它该不该**：
系统只维护「这一轮它说自己在第几步」这个事实。**唯一的自动反应仍然是「停」**（§2.5），
而不是「纠正它」。

⚠️ **合规率是未知数（猜测）**：模型会不会老老实实打那个标记，没量过。
**定它的办法**：Task 1 顺手量一次（同一条描述跑 1 次，数标记覆盖率）；
**万一它不报**，位置就退化成「只有页面变化」——**系统照样能跑**，
只是 `plan_ledger` 会空一些。**这是降级，不是失败**，因为 §2.5 的停滞判据不依赖标记。

### 2.5 偏离与停：**别把规则折叠请回来**

**本设计不许做的事**（每一条都是「规则折叠」的变体，那条路已经死了，§1.1）：

- ❌ 用关键词判「这一步该点哪个按钮」
- ❌ 用规则判「这一步完成了没有」
- ❌ 把描述编译成 py / 选择器（那就是旧的 `py_emitter` 那条路）
- ❌ **把「步数对不对」当异常**（§2.2：分支站的步数**本来就会变**，20 / 33 / 34 都正常）——
  任何以「期望 33 步」为前提的判据（差值、超时、上限）**都是错的**

**允许的、也是唯一的自动干预是「停」**：

```
一轮里，若：位置标记没前进  且  页面状态没变  且  这一步没成功
   → 连着一个 STALL_LIMIT 轮如此 → _Stop("plan_stalled")
```

- **判据全是感知/声明**（标记、页面状态、`result.ok`），**没有一条是语义判断**
- 停下来的形状与今天**完全一致**：`_Stop` → `stop_reason = "plan_stalled"` →
  `_explore` 判 `END_EXPLORE_UNFINISHED`（`agent/graph.py:348`）→ 人话里带上
  **它卡在第几步、卡在哪一句描述上**（`explore_say` + 闸口 facts）

## 六、不采纳的方案与理由（免得下一个人重走）

| 方案 | 为什么不 |
|---|---|
| **更细的图节点（一轮 = 一个节点）** | ① 新窗口是**空白**的，位置**必须重走**才回得去 —— 细节点只省模型轮数，回不去那一页照样回不去；② 人那道闸从一次变几十次，Console 的「一轮 = 一道闸」整个模型要重做；③ `NODES` / `WINDOW_STEPS` / `_resume_point` / `visits` 全要改；④ checkpoint 写入 × 轮数。**花的四项成本买不到位置** |
| **把 journal 放进 checkpoint（`state["journal"]`）** | LangGraph 的节点**中途写不了状态**（返回值在节点结束时才合并）→ 做不到「发生的那一刻就落盘」。**只有读得出「已提交的节点」**，那正是今天的问题 |
| **重放交给模型**（把历史塞回对话让它自己走回去） | 那正是要省掉的东西。模型轮数是这次的**病根**，不是手段 |
| **在工具层加 `submit` 之类的语义工具** | 往工具层塞判断 = D11 的正面冲突（`observe` 的描述里写着不许）；而且 Go 侧要改，本片明确不碰 |
| **把不可逆的判据做成关键词表**（"submit"/"发送"/"确认"） | 规则折叠的变体。§1.4 的规则全部只用人给的成功判据 + 账本已有的事实 |
| **重放时跳过失败的步接着走** | R-35 那次失败的形状（静默跳过 → 报告看不出来）。一律**停下说话** |
| **保持 `max_rounds` 为「每次尝试」的上限** | 窗口反复死时那根线**不响**（§1.8）—— 「防跑飞」名存实亡 |
| **把描述当成一条固定路径的脚本**（「33 步」= 站点结构） | 问卷/评测类是**分支**的：同一条描述，20 / 33 / 34 步都合法（人 2026-09-17 指出）。照固定步数写任何判据（期望值、差值、进度百分比）都会在另一条分支上**误判** —— 那是把规则折叠又请回来的一种（§2.2 / §2.5） |
| **把「没走到的检查点」也记进 `deviations`** | 分支站上这会灌满日常噪音 → §6.3「同一处反复偏离」那条信号**失效**（§2.3.1） |
