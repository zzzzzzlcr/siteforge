## 零、为什么有这一片

**第一动机（R-41）**：真站验收失败在**人看一眼截图就能发现**的那类问题上（站点把落地页换成轮换变体
`cr640` → `gt1791-1`，于是 `when` 一条都不成立、**每一步都被静默跳过**），而 agent 自己绕不出来。
当时定的方向是「至少要有界面看到」。

**第二动机（v2，2026-09-17，用户看完一次真运行之后）**：

> 「他这样子一直执行，我也没办法介入，也没办法知道他为啥要关闭。跟我们 claude code 聊天开发 py 脚本
> 我还能充当他的眼睛或者纠错员，完全不一样，**我依旧没办法介入**。」

**这句话把基准换掉了。** v1 那一片（每道闸一句话 + 一对图 + 两个按钮）是**回放器**：
它让人**事后**看得见，但坐在屏幕前的人**当下**仍然是旁观者 —— 这恰好是用户说的「不一样」。
真正的基准是**他每天在用的那个东西**（claude code 聊天开发 py 脚本）：

| 他在那边能做的 | 这一片必须给的 |
|---|---|
| **它做什么、为什么，当下就看得见**（不是状态字段，是它在说话） | 一条**照着发生的顺序长出来**的时间线：它的动作、它自己的话、系统的解释 |
| **随时打断或纠正**，不是只在指定停点 | 「停」随时可按（落点诚实），input 一直开着 |
| **他的观察改变下一步**（「卡在姓名那一栏了」→ 它就换做法） | 他在探路里说的话，**下一轮就进到它眼前** |
| **出了事有人说话** | 「窗口死了 / 被重开 / 某遍没跑 / 撞上限 / 量不出来」——**每一条都变成一句人话，带时间戳，落在时间线上** |
| 他只是**一个人盯着一趟运行** | 这一片的全部设计目标就是这一个场景 |

**那次真运行里最刺眼的一条**：窗口死了、又被重开了，**全程没有任何人被告知** ——
这件事系统**知道**（它在 `BitWindow.alive()` 的三态探针里、在 `reopen` 的那句话里），
但那句话只活在「服务自己的 `job.say`」和「那个调用方拿到的 409 响应体」里，
**坐在屏幕前的人一个字都看不到**。这一片要修的首先就是这个形状：
**凡是系统已经知道的事，都必须说给那个在看的人，而且是在它发生的时候。**

## 一、边界与验收

### 1.1 这一片是什么

**一个人，一趟运行，一个能看、能说、能停的页面。**

- **看得见**：时间线（动作 / 它的话 / 系统的解释，逐条带时间戳）+ 每轮一张卡片（一句话 + 一对图）；
- **说得上话**：input 一直开着 —— 停在闸上就是那道闸的回话；正在跑就排队（探路里**直达**）；
- **停得下来**：「停」随时可按，**落点诚实**（§四：探路里几秒内，别的步骤跑完那一步，闸上立刻）；
- **问得到为什么**：系统知道的每一件事都变成时间线上的一句话（§三.2 的目录表）。

### 1.2 明确不做（这一片不做，理由在 §十一）

**R-41 原本就划掉的**：框选元素、patch 预览（py diff → 验证 → 合并）、记忆层、多用户。

**v2 新增划掉的**（都是「离得最近的下一步」，所以更要写清）：在中途停**别的**节点、
停下之后**接着走**（替代品是 `/again` 重新发起）、把活窗口**内嵌**进页面、**跨趟**的对话历史、
给运营看的**提单表单**、逐运行的**鉴权**。

### 1.3 验收（用运营自己的话写）

> **一个人坐在屏幕前，自己一趟一趟地在闸上回话，盯完一趟真运行。**
> 全程他能随口回答四个问题：**① 它现在在干什么？② 为什么？③ 我刚打的那句话去哪了？④ 我要是按停，会怎样？**
> 而且 —— **没有任何一件事是「发生了但没人说」**：窗口死了、窗口被重开、某遍扰动没跑、
> 撞上限、探针量不出来、图没拍成 —— 每一条都在时间线上，**有时间戳、有人话、说的是为什么**。

**不是**「修好」（那是完整 Console 的验收）；**也**不是「能回放」（那是 v1，被用户否了）。
可证伪的检查项在 §十二（A1–A12）。

## 三、时间线：谁在什么时候说话

### 3.1 时间线是什么、不是什么

**是什么**：一趟运行**照着发生的顺序**长出来的一串事件，每条 `{n, at, kind, who, say}`：

```jsonc
{"n": 12, "at": "2026-09-17T14:02:22+08:00", "kind": "agent_step", "who": "agent",
 "say": "第 2 步：点了「Get Started」"}
{"n": 13, "at": "2026-09-17T14:02:27+08:00", "kind": "human_said", "who": "you",
 "say": "不是那个按钮，是下面那个"}
{"n": 14, "at": "2026-09-17T14:02:27+08:00", "kind": "steer_delivered", "who": "system",
 "say": "你这句话已经交给它了 —— 它下一轮就会看到。"}
{"n": 15, "at": "2026-09-17T14:05:02+08:00", "kind": "window_died", "who": "system",
 "say": "窗口没了 —— Bit 的窗口只活几分钟。它停在「写这一版 py」之前，接着走之前得先重开一个窗口。"}
```

- `n` 单调递增（**排序用 `n`，不用时间戳**：同一秒里可能来两三条）；
- `who ∈ {agent, system, you}` —— 页面靠它决定气泡长相（它就是「聊天」那一半）；
- `say` **永远是人话**（D16）：不是错误码、不是选择器、不是 JSON。原始事实放 `data`（默认不显示，排查时展开）。

**与「轮次 + 截图」的分工**（这条必须写清，否则两块会互相长）：

| | 时间线 | 轮次卡片 + 一对图 |
|---|---|---|
| 回答 | **它现在在干什么、为什么**（过程） | **这一轮做成了没有**（结论 + 证据） |
| 什么时候有 | **当下**，一条一条长出来 | 每次**停下**时定稿一张 |
| 从哪来 | 服务与 agent 的回调（内存里的 `Job.events`） | **从 checkpoint 投影**（R-19：状态在 saver 里） |
| 服务重启后 | **没了**（§三.5，明说） | **还在**（重新投影就有） |

一句话：**时间线是现场，轮次与截图是档案。** 两者都要，因为它们回答的不是同一个问题。

### 3.2 「为什么」的句子从哪来（**这一节是这一片的核心**）

系统已经知道、而坐在屏幕前的人**看不到**的那些事实，逐条点名 —— 每一条都要变成时间线上的一句话：

| # | 事实 | 谁知道（出处） | 今天说给谁听 | 时间线上那句话 |
|---|---|---|---|---|
| 1 | **窗口没了** | `BitWindow.alive()`（`agent/service.py`，**三态**：True/False/None） | **谁也没听到**：只在 `reply()` 里被问一次，用来**拒绝**回话（409 detail 返回给调用方） | 「窗口没了 —— Bit 的窗口只活几分钟（实测过）。它停在「%s」之前；接着走之前得先重开一个窗口。」 |
| 2 | **窗口被重开** | `Service.reopen()` | 写进 `job.say` —— **下一次 `_advance` 就把它冲掉了** | 原话照搬（它本来就写得很好）：「窗口重开了，探路要从头再走一遍（页面状态没了，账本得重新收）…」/「…从上次停下的地方接着跑（探路那一段不重来）」（**两个分支两句不同的话**，别合并） |
| 3 | **某遍扰动没跑** | `selftest.Report.runs[i].status == "skipped"` + `.note` | 只在 `selftest` 那一轮的 `facts` 里，要展开才看得到 | `on_run` 当场一句：「第 4 遍（换个窗口大小）**没跑**：换窗口大小要调用方在窗口层动手… —— 这一类失败这次**没验到**」（note 原文已经是人话，照搬） |
| 4 | **撞上限** | `end_reason ∈ {lint_cap, selftest_cap, revision_cap}` + `end_note` | 只在下一次停下时的一次性 `say` 里 | 事件 + 卡片都留着：「停：这一版 py 被打回 2 次还是同样的地方不过…（§6.3 的信号）」 |
| 5 | **探针量不出来** | `Service._viewport_cb` 抛的那句（它是故意写得那么清楚的） | 变成「这一遍没跑」的 note（只有展开才看得到） | 同 3（note 原文照搬：「换窗口大小之后量不出活窗口现在多大…把它当成「没验到」」） |
| 6 | **图没拍成** | `shots_why` / 闸拍的 `why` | 只在这一片的卡片上 | 「这一步没留下图：窗口连不上」（**不许**让空图框冒充页面） |
| 7 | **排队等窗口** | `Service._view` 的 queued 分支 | 只在那一次的 `say` 里 | 「排队等窗口（前面还有别的 run 在用）—— 它还没开始跑。」 |
| 8 | **服务重启过、job 是捡回来的** | `Service._recover()` | 只在 `job.say` 里（也是被冲掉的） | 「（服务重启过：这个任务是从 checkpoint 里捡回来的）」 |
| 9 | **人说过的话 / 人打过回** | `reply()` 的 `note`、`revisions` | 只在 state 里（要到 `draft` 那一步才在 `facts` 里露出来） | `who: "you"` 那一条 + 「这句话会一路带进「写这一版 py」」（**说了就要让人知道它去哪了**） |
| 10 | **它自己的话与动作** | `_Gate` 的 `AI 说：…`、`on_step` 的 `note` | 只在 `Journey` 里（跑完才看得到，还要展开） | §3.3 |
| 11 | **跑挂了** | `_advance` 的 except：`job.error` + 那句 `say` | 只在那一次的 `say` 里 | 事件（带原始错误）+ 卡片；**跑挂 ≠ 跑成**（服务不肯做的那条第 4 条） |

**落地的形状**：`Job.events`（append-only，`Service.narrate(job, kind, say, who="system", **data)` 是唯一的写入口）
+ 上面每一条事实各自的**触发点**。两条硬规矩：

1. **凡是往时间线写的东西，`say` 必须是人话** —— 写不出人话就说明还没想清（这是 §6.6 那条「对话 > 审批」的落地形态）。
2. **不许有「静默」的路径**：任何一个 `except`、任何一个 `skipped`、任何一个 `why` 字段，
   都必须有一条对应的事件。**没有事件的异常 = 这一片没做完。**（验收 A11 就是扫这个。）

### 3.3 它自己的声音（**「它在说话」，不是「状态在变」**）

`agent/browser_agent.py` 里那两处已经在记人话，只是没人在跑的时候看得到：

- **每一步**：`dispatch` 里 `step["note"] = _say(...)` —— 「点了「Get Started」」「没找到「Yes」这个输入框，没填成」；
  通过 `on_step`（**这个参数本来就有**，docstring 写着「Console 的实时视图靠它」）接到时间线；
- **每一轮模型的话**：`_Gate._note` 往 `journey.notes` 追加的 `AI 说：{content}` —— 这是**它的推理**，
  也是「我能充当他的眼睛或者纠错员」这句话里最需要的那一半。今天它只在跑完之后才看得到；
  这一片加一个 `on_note` 回调，**当场**接到时间线。

于是正在跑的探路在页面上长得像这样（这就是用户要的那个东西）：

```
14:02:14  它     AI 说：先看看这一页有什么 —— 我要找一个「Get Started」按钮
14:02:15  它     第 1 步：看了一眼页面
14:02:20  它     AI 说：页面上有一个 Get Started，在首屏，先点它
14:02:22  它     第 2 步：点了「Get Started」
14:02:26  它     第 3 步：看了一眼页面
14:02:27  你     不是那个按钮，是下面那个
14:02:27  系统   你这句话已经交给它了 —— 它下一轮就会看到
14:02:31  它     AI 说：明白，我改点下面那个 Yes
```

**代价**：一次探路 30 步 → 时间线上多几百条短字符串（内存里，随 job 一起活在进程里）。
与「看不清它在干嘛」比，这个代价不值得讨论。**唯一的注意**：`on_step`/`on_note` 都从**工作线程**里回调，
写 `Job.events` 要拿锁（`job.lock`，一把只包住一次 append 的短锁）。

### 3.4 你说的话：三种状态，行为不同

| 它现在的状态 | 你打字然后回车 | 页面说什么 |
|---|---|---|
| **停在闸上（`waiting`）** | 这句话就是**那道闸的回话**（input 里还预填着排队来的话） | 两个按钮：「继续」/「说一句，接着走」（`revisable` 时叫「打回带话」，§九） |
| **在探路里跑（`running`，当前节点是 explore）** | **直达**：进它的**下一轮**（`llm.run_tool_loop` 在下一次模型调用之前把这句话作为一条 user 消息插进去） | 「已经交给它了 —— **它下一轮就会看到**（一轮几秒到几十秒）」 |
| **在别的节点里跑 / 排队中** | **排队**：进 `Job.inbox`，时间线上立刻出现你那条 + 「已记下 —— 它正在「自测」这一步里跑，这一步**中途停不下来**；这句话会在它停下来时进到输入框，你按一下就能送过去」 | 见 §四 |

**为什么「直达」只做在探路**：`llm.run_tool_loop` 是探路的模型循环，那里天然有「下一轮」这个插入点；
别的节点（起草 / 检查 / 自测 / 落盘）要么不调模型，要么是一段不能被打断的确定性流程，
**要插话就得先把它们改成可中断的** —— 那是另一片（§十一）。
一半的插话（说了但没送到）比不做更坏：人会以为自己已经纠正过了。

⚠️ **直达有一个已知风险，必须写下来**：插进去的这句话可能让模型**不调工具、直接收尾**
（那道门上没有 `done()`，「不调工具」= 它宣布讲完了 → `stop_reason = model_done` → 图会认成「探路走完了」）。
处置：交给它的那句话里**明说**「这是人插的话，接着探，别把它当成收尾」，
并且**插话之后那一轮如果它就收尾了，就往 `journey.notes` 里追一句人话**
（「你插话之后它就收尾了 —— 看一眼它的结论对不对」），让人在时间线上看得见。见风险表 R11。
**真站上验不过就走退路**：`input.mode` 一直停在 `queue`（页面文案跟着 `mode` 走，自动变成
「会在它停下来时送到」）—— **不许**留着一条「说了但没送到」的路还不告诉人。

### 3.5 时间线**不持久** —— 这一条要明说

`Job.events` 活在**服务进程**里（和 `_jobs` 登记表一样）。服务一重启：

- **时间线没了**（现场的对话记录）；
- **运行本身还在**：状态在 checkpoint 里（R-19），轮次与截图能重新投影出来（档案）；
- `/live` 的 `note` 字段**明说这件事**：「服务重启过：这之前的时间线没有了。运行的状态还在
  （从 checkpoint 里读），轮次与截图仍然完整。」

不把事件写进 checkpoint 的理由：事件是**高频、只有人看**的东西，写进状态会让每一次
`invoke` 都拖着它走一遍序列化 —— 而 checkpoint 是**给恢复用的**，不是日志。
（真要持久的时间线，该落在产物侧的 trace / 一个 append-only 的表里，那是另一片。）

## 四、随时介入：诚实的边界（**「停」按下去到底会发生什么**）

### 4.1 那个按钮叫「**停下，我要说一句**」

它的真实语义**不是**「立刻冻结」，而是「**别再往下走了，我要说话**」。三行矩阵，**原样上页面**：

| 它现在在哪 | 停的落点 | 页面说什么 |
|---|---|---|
| **探路里跑** | **几秒内**（`should_pause` 每步之前、每轮之前各查一次）→ 探路**当场结束**，这一趟以 `paused` 收尾 | 「停下了（几秒内）—— 探路的账本不完整（页面状态没了），要接着做就得重来一次。**你说的话我记着**，按「重新来一遍」会带上。」 |
| **别的节点里跑**（起草 / 检查 / 自测 / 落盘） | **跑完这一步**：这些步骤中途**没有**停的口子。它跑完就会停在**下一个闸口**——而那个闸口**本来就在等你** | 「现在停不下来：它在「自测」里。不过**它做完这一步一定会停下来问你**（每一步之前都停），所以你要做的只是**什么都不按**。你刚才说的话我排好了，到那儿会进输入框。」 |
| **已经停在闸上（`waiting`）** | **立刻** == 回一句 `{"action":"stop"}`（这一步**不会做**，`end_reason=human_stop`） | 「停下了。这一步没有做，页面与文件都是原样。」 |

**为什么第二行不是敷衍**：因为 `_enter()` 在**每个节点之前**都 `interrupt()`（§6.2 的架构约束），
所以「跑完这一步就停」不是承诺，是**本来就成立的事实**。这个按钮真正多做的事只有一件：
**让停下来的那一刻，你说的话已经在输入框里**。

⚠️ **一条不对称的授权**（写进 Global Constraints）：**服务可以替人「停」，绝不替人「走」。**
「停」不会让任何一步发生（它是**阻止**）；而替人回一句「继续」会让**一步在没人看着的情况下跑掉**
—— 那正是 `c998a72` 那次修复钉住的事故。所以探路的 `should_pause` 由「停」请求驱动（安全），
但**没有任何一条路径会因为超时、因为排队、因为「看起来没人管」而自动继续**。

### 4.2 说一句：它到底去哪了

- **在闸上** → 就是那道闸的 note（`hints` → 一路带进 `draft`；`revisable` 的闸上还会触发「回 draft 重写」）。
- **在探路里** → 下一轮直达（§3.4），并且时间线上有「已经交给它了」。
- **在别处** → 排队（`Job.inbox`），到下一道闸进输入框；**不自动发**（人按按钮才发）。
  时间线上你那条的旁边一直有一个「还没送到」的标记，送到之后消失。

### 4.3 这一片**不做**的两件（离得最近，所以说清）

1. **中途停别的节点**（自测跑到第 3 遍想停）。要做得先把那几个步骤改成可中断的：
   `selftest` 的五遍共用一个子进程循环，现在只有「整段跑完」这一个出口。**能做，但是另一片。**
2. **停下之后再接着走**（`paused` 的 run 从断点续上）。今天的 `reopen` 接得住「窗口那一支」两步
   （`explore` / `selftest`），`paused` 不在里面；而且探路一旦停下，**账本已经不完整**，
   「接着走」等于「重探一遍」—— 那和重开一趟是同一件事，只是多一套状态。
   替代品是 **`/again`**：拿**同一份开场白** + **你说过的话**，重新发起一趟（新 job、新时间线）。

## 五、Q1：截图从哪儿来

### 5.1 先说清：活窗口、时间线、截图，各管一段

| | 活窗口（人连到 worker 上看） | 时间线 | 截图 |
|---|---|---|---|
| 看什么 | **当下**的全保真页面，还能接管（鼠标键盘） | **过程**：它在做什么、它说了什么、系统知道什么 | **某一刻的画面**：点前 / 点后 |
| 什么时候有用 | 人**正守着**的时候 | 人**一直在看**的时候（它就是「一直在看」的载体） | 人**回头看**、或者要**并排比一下**的时候 |
| 做不到 | 人不可能一直盯；过去的那一趟没了（窗口只活几分钟，P6）；几个运行没法同时开几个远程桌面 | 看不见页面长什么样 | 不能实时、要花 CDP 命令（§5.5） |

**截图独有的那一件事**：「**那一下点击到底有没有用**」。
**页面没变 ≠ 动作没做**（点了个不推进的按钮、点到了别的东西、点在被遮住的位置）——
人在活窗口上盯着**也未必看得出**「刚才那一下动了没有」，而点前 / 点后并排两张**一眼**就看出来
（D16 的「XX 没点」就是这个东西）。所以截图留着，但它**只是三样里的一件**。

### 5.2 现状（读代码得到的，不是推的）

| 事实 | 出处 |
|---|---|
| 截图**能力有**，且已在镜像里 | `tools/cdp/cmd/screenshot.go`（CLI：`--out` 落盘 / 默认吐裸 base64 / `--json` 附坐标证据）；`tools/cdp/internal/mcp/registry.go:356` 那道 MCP 门上也挂了 `screenshot`；`Dockerfile` 把两个二进制都 COPY 进镜像 |
| **没人每步去拍** | `agent/browser_agent.py` 的 `Journey` 只记 `{state, action, target, result, note}`；`_summarize` 对 `screenshot` 只记 `bytes`（长度），字节不落盘 |
| 产物那边**已经有**一套成熟的每步抓拍策略 | `agent/template.py`：`--shots failed`（默认）/ `--shots all`；`shot_before` 常拍，动作后**只在「没做成」或「判得出没推进」时留**，否则删掉点前那张；trace 的键就叫 `shot_before` / `shot_after` / `shots_why` |
| 服务这一层**知道窗口**，也**已经在直接调 cdp 二进制** | `agent/service.py` 的 `BitWindow`、`live_viewport()`（`ws_url` → host/port → `cdp eval`） |
| 图**每步之前**都停 | `agent/graph.py` 的 `_enter()`：每个节点开工第一件事就是 `interrupt()` |

⚠️ **一个必须先说清的坑**：`llm.run_tool_loop` 会把工具的**整个返回值** `json.dumps` 进 tool 消息
（`agent/llm.py:183`）。所以**模型自己调 `screenshot` = 把 ~500KB base64 塞进上下文**。
本片的抓拍**一律走旁路**（我们自己调那道门 / 调 CLI），**绝不**经过模型的消息通道 —— 这是设计约束，不是优化。

### 5.3 决定：两条来源

| 谁拍 | 什么时候 | 拍什么 | 为什么是它 |
|---|---|---|---|
| **服务** | **每次 `invoke()` 返回之后**（= 图刚停下），一张 | 活窗口的当前视口 | ① 服务是**知道窗口的那一层**；② 这一刻正是**人要拿主意**的时刻，图停了、窗口没人在用；③ 服务已经有一条「直接调 cdp 二进制」的先例（`live_viewport`） |
| **探路 agent** | **动页面**的动作（`click`/`form`/`scroll`/`goto`）：点前一张；**点后只在已经知道不对劲时补** | 点前 + 点后一张（**只有可疑的步才凑得成一对**） | 只有它挨着**步**的边界，也只有它手上有「上一次观测到的页面模型」（判断「页面动了没有」需要的那点信息） |

**不拍的**：`observe` / `diff` / `screenshot` 这些感知动作；非浏览器节点
（`draft` / `lint` / `deliver` 不碰页面 —— 卡片上要**明说**「这一轮写的是文件，页面没动」，而不是画一张看不出所以然的图）。

### 5.4 步拍策略（**留的只有「不对劲」的那些步**）

```
只对 MUTATING（click / form / scroll / goto）拍；observe / diff / screenshot 不拍

点前：动页面的动作**之前**拍一张                      → 1 条命令（每个动页面动作都有）
点后：只在**已经知道这一步不对劲**时才拍：
        a) 这一步 ok 为假（**当场**就知道）            → 动作返回后立刻补拍
        b) 做成了、但**紧接着**那次观测显示页面签没变   → 在观测那一刻补拍（并标 shot_after_deferred）
              ⚠️ **b) 只对 `click` / `goto` 成立**（见下面判据 2 的注）
留：只有 a、b 两种情形留「点前 + 点后」；其余情况**把点前那张删掉** —— 一张都不留
```

三条判据：

1. **留的集合 = {没做成} ∪ {做成了但页面没变}** —— 正是「哪一步不对」的那两步。
   一次**跑顺**的探路可以**一张都不留**（闸拍那张除外）。（产物 `--shots failed` 的同一条判据。）
2. ⚠️ **「页面签没变」只对 `click` / `goto` 成立**（2026-09-18 裁定）。
   签取的是 `page_text`，而它是 `body.innerText` —— **填框不改它、滚动也不改它**。
   拿它判 `form` / `scroll` 是**必然假阳性**：2026-09-18 实测，一趟**全部成功**的漏斗
   （3×form + 1×scroll + 1×click）因此留了 **10 张**，而 `MAX_KEPT_SHOTS = 40` 会被
   **健康步**吃掉 —— 真正不对劲的步反而没有图。**只对这两个动作判，其余按「判不了」办。**
   这张表与产物侧是同一张（`agent/template.py` 的 `DIFF_JUDGES`，它在**模板字符串里** ——
   生成的 py 独立跑、不能 import `agent`，所以**结构上免不了两份**；
   `agent/browser_agent.py` 里那份有**防漂移哨兵**盯着，见 `test_the_two_diff_judge_tables_agree`）。

2b. **「页面签没变」是免费信息**：`_Pages` 已有的 `(url, title, page_text[:400])`（`note_page` 的 `key`），
   下一张 `observe` 一到就能比 —— 不额外发命令。判据只在**紧接着**的那次观测上生效
   （`click A → click B → observe` 不认：那时「没变」说不清是谁造成的），认不出来就按「不留」。
3. **点前那一条命令是下限、省不掉**：要在动手**之前**知道这一步会不会出问题是不可能的。
   所以「只对可疑的步拍」落在**留**上，落不到**拍**上；能省的只有**点后**。

⚠️ **b) 那张是「随后补拍」的，必须标注**：判据只在紧接着的那次观测上生效，所以两次之间**没有别的动作**，
补拍那一刻与「动作刚结束时」隔的只是一次观测，而页面的签在中间没变 —— 那张图**应当**一致。
但**签不变 ≠ 像素不变**（spinner / 布局抖动 / 图片换了），所以数据里带 `shot_after_deferred: true`，
页面上给这一张打一行小字（「随后确认时补拍」）——**不许**把两种来源的图显示成一模一样的东西。

另外两条与产物同源：**上限** `MAX_KEPT_SHOTS = 40` **张**（到顶就不再拍，并往 `journey.notes` 写一句人话）；
**拍不成** → 记 `shots_why` 人话 + **时间线一条事件**，探路照常往下走（拍照永远不许把探路搞挂）。

### 5.5 代价（摊开算）

| 项 | 数 | 说明 |
|---|---|---|
| 闸拍 | 1 条 CDP 命令 × 轮数 | 典型 **≤ 12**。**发生在图停下之后** → 不占 agent 的时间，只占工作线程 |
| 步拍 · 点前 | 1 条命令 × **动页面**步数 | 典型 ~10–15 条（§5.4 判据 3：这是下限） |
| 步拍 · 点后 | 只对可疑的步 +1 条 | **跑顺的一次运行通常 0 条** |
| 留下的 | 只有「没做成」与「页面没变」的 | 跑顺的运行**一张都不留**（闸拍那张除外） |
| 磁盘 | ~0.2–0.5MB/张，上限 40 张/次 + 每轮一张闸图 | 最坏 ~20MB，`runtime/` 不进 git |
| **合计（猜测）** | **~20–27 条 CDP 命令/次运行** | 按 0.2–0.6s/张 → **4–16 秒**，加在一次本来就要**几分钟**的运行上 —— 约 **2–5%** |

**单张多少钱 = 没量过，是猜测**（视口 ~393×852 的 PNG base64 约 200–550KB，走 worker 的 CDP websocket
一个来回，猜 0.2–0.6s）。**必须量，不许猜着上线**（Task 1 Step 5）。量出来之后的岔路：

- **≤ 1.5s/张** → 按 §5.4 做（主路）；
- **> 1.5s/张** → **降级 B**：关掉每步抓拍（`SITEFORGE_STEP_SHOTS=0`），只留闸拍。
  ⚠️ **不许静默降级**：`/live` 会带一句人话（`shots_note`），**页面上一直显示**它
  （「这一次没留逐步的图：截图实测 X 秒/张，太贵。每一道闸拍的那张还在，逐步的一句话清单也还在。」）。
- **为什么不一开始就只做闸拍**：验收问的是「卡在哪一步」，而一次探路是**一轮里的 30 步**。

### 5.6 字节落在哪

```
runtime/shots/<job_id>/pause-<n>.png           ← 闸拍（服务拍）
runtime/shots/<job_id>/step-<n>-before.png     ← 步拍（agent 拍）
runtime/shots/<job_id>/step-<n>-after.png
```

`runtime/` **不进 git**（`selftest._default_run_dir()` 已有先例，同层不同目录）；根可配 `SITEFORGE_SHOTS_DIR`；
**清理不在这一片**；产物自测留下的那几张（trace 旁边）**顺带**能服务，但不在验收里。

## 六、Q2：「一轮」是什么

**一轮 = 图的节点：两次「停下」之间那一段**（`_enter()` 在每步**之前** `interrupt()` 的产物）。

为什么不是另外两种：

| 候选 | 为什么不选 |
|---|---|
| **模型的一轮** | 它是**探路内部**的实现细节，图看不见它、也没停在它上面 —— **没有停就没有「回话」这件事** |
| **一个动作** | 图**不**在动作边界上停。`should_pause` 是**「停下」信号**、不是可恢复的中断（把探路打断就是整段结束） |

**步怎么办？** 步不消失，它换了个位置：**轮是「回答」的单位，步是「证据」的单位，
而「过程」由时间线承担**（§三）。一张轮卡片两层：

```
第 3 轮 · 打开浏览器探路                          ← 轮（= 图的节点）
  它刚要做什么：接下来要打开真浏览器，把「…」走一遍：「…」   ← 闸口的 say
  现在窗口里是这样：[图]                          ← 闸拍
  ── 刚才那一步（intake）做了什么 ──────────────
  收到：站点 example-funnel，目标是…
  [点前 图]  [点后 图]                            ← 夹住刚才那个节点的一对
  ── 探路里它走的每一步（30 步，折叠）────────────
  第 7 步  点了「Get Started」   页面没有变化 ❌   [点前][点后]
  …                                              ← D16 的「XX 没点」长在这一层
  我要它怎么做：[________________]  [继续] [说一句，接着走]
```

**配对规则（写死）**：第 n 道闸上拍的那张叫 `pause-<n>`：

```
rounds[n-1].step       = gate.step                    # 这一轮**正要**做的
rounds[n-1].now        = pause-<n>                    # 现在窗口里是这样（轮 1 也有）
rounds[n-1].done.step  = values["visits"][-1]         # 刚做完的那个节点
rounds[n-1].done.shots = (pause-<n-1>, pause-<n>)     # 夹住刚才那个节点的一对
rounds[0].done         = None                         # 第一道闸之前什么都没跑
```

一对图夹的是「**刚才那一步**」，不是「正要做的这一步」—— 因为闸在节点之前：站在闸上时这一轮还没跑，
没有「点后」。人也正是**看着结果**才决定要不要继续。`now` 与 `done.shots.after` 是**同一张文件**
（一份字节、两处引用），页面别显示两遍。

## 七、Q3：怎么服务（零构建步骤）

**`GET /console` 出一个单页 HTML（`agent/console.html`），由 `agent/service.py` 同源发出。**
页面从上到下三块：**时间线**（聊天式的、随时间往下长）、**轮次卡片**（最新一轮在最上面、
折叠着历史）、**底部常开的一行输入** + 两个按钮 + 「停」；最下面那块是「这个窗口」（§十）。

| 取舍 | 选择 | 理由 |
|---|---|---|
| 构建步骤 | **不要**（无 npm / 打包 / 框架） | 这个项目的全部价值是「人能读、能信每一块」；为此在镜像里塞一条 JS 工具链，是拿最贵的东西换最便宜的东西 |
| 外部资源 | **一个都不许**（无 CDN / 字体 / 图标库） | 运营的浏览器在内网里，出网要过代理 —— 一个 `src="https://…"` 就是一张永远转圈的空白页 |
| 数据通道 | **轮询**（2–3 秒），不上 websocket / SSE | 轮次的粒度是「几十秒到几分钟」；而**时间线**那条要的是「几秒内看到」—— 2–3 秒的轮询刚好够，多一套长连接换来的延迟改善人眼分不出 |
| 谁发这个页面 | 同一个 uvicorn（8080） | 同源 = 没有 CORS、没有第二个端口、没有第二个进程；`entrypoint.sh` 一个字不用改 |
| 页面放哪 | 仓库里的 `agent/console.html`，路由读文件返回 | 页面是**可读的资产**（能 diff、能 review），不是塞在 py 里的字符串 |

**代价明说**：页面的 JS **没有单测**。对策不是补一套 JS 测试框架，而是**把 JS 做笨** ——
只做「取 JSON → 拼 DOM」，状态只有两个（`job_id` + 轮询定时器）。能自动断言的都留在 HTTP 层。

## 八、Q4：什么带数据

### 8.1 端点一览

| 端点 | 干什么 | 形状 |
|---|---|---|
| `GET /job/{id}/live` | **页面的唯一数据源**（2–3 秒轮询它一个就够） | 见 8.2 |
| `GET /runs` | 「能挑运行的最小列表」 | `{note, runs: [{job_id, site, status, say, created_at, rounds, delivered}]}` |
| `GET /job/{job_id}/shot/{name}` | 一张图 | `image/png`（名字白名单 + 解析后必须落在 `<shots_root>/<job_id>/` 之内） |
| `POST /job/{id}/say` | **常开输入**：现在没人在等我的那种情况（§九.2） | `{queued｜delivered, n, say}` |
| `POST /job/{id}/stop` | 「停下，我要说一句」 | `{stop: {requested, where, will_stop_at, say}}` |
| `POST /job/{id}/again` | 同一份开场白 + 你说过的话，重新发起一趟（§四.3） | `{job_id, say}` |
| `POST /job/{id}/reply` | **不动**：闸上的回话（继续 / 带话） | 既有形状 |
| `GET /job/{id}` | **不动**（别处读它） | 既有形状 |

### 8.2 `GET /job/{id}/live`

```jsonc
{
  "job_id": "job-9f3a1c02d4e5",

    {"n": 13, "at": "…", "kind": "human_said", "who": "you",   "say": "不是那个按钮，是下面那个"},

  },

    "placeholder": "写一句它该怎么做，或者按「继续」让它往下走",
    "draft_note": "不是那个按钮，是下面那个",   // 排队的话到了闸上会预填在这儿（**不自动发**）
    "queued": [{"n": 31, "say": "…", "at": "…"}]
  },

  },

  "rounds": [ /* §六 的卡片，含 now / done.shots / steps / shot_after_deferred */ ],
  "truncated": false              // 轮次或事件超过上限时为 true（并说明）
}
```

### 8.3 为什么这样分（四条判据）

1. **一个轮询喂一个页面**：页面只有一个 `job_id` + 一个定时器，**取一份 JSON 就画完**。
   分成几个端点会让「时间线说在跑、卡片还显示在等人」这种自相矛盾的画面变得可能。
2. **字节不进 JSON**：一次 12 轮、每轮两张图的运行，塞 base64 会让**每次轮询 ~7MB**，
   而内容每次都一样。图走 `/shot/`（能被浏览器缓存，文件名带轮号，内容永不变）。
3. **不编话**：每句 `say` 只从它该来的地方来（`_Project` 的闸口原话 / `journey` 的 `note` /
   `report.summary()` / `end_note` / 服务自己的 `narrate`）。state 里没有就写「这一步没说它做了什么」。
4. **不给运营看选择器、原始 JSON、错误码**（D16、§6.6 的反面）：主视图只有人话 + 图 + 时间戳。
   `target.selectors`、`observe` 的 JSON、149 个元素的表 —— 一个都不进。

## 九、Q5：输入与三个动作

### 9.1 三个动作（都映射到**已有**语义，不新增后端行为）

| 动作 | 请求 | 图那边发生什么 |
|---|---|---|
| **继续** | `POST /job/{id}/reply {"action":"continue"}` | 这一步照做 |
| **说一句，接着走**（`revisable` 时叫**打回带话**） | `{"action":"revise","note":"…"}` | `lint`/`selftest`/`deliver` 三道闸上 = **这一版不要了，回 `draft` 带他的话**；别的闸上 = **接着说一句**，那句话进 `hints` 一路带进 `draft` |
| **停下，我要说一句** | `POST /job/{id}/stop` | §四.1 的三行矩阵 |

⚠️ **按钮的名字必须跟着 `revisable` 走**：在 `intake`/`explore`/`draft` 三道闸上它叫
**「说一句，接着走」**，旁边一行小字说清「这不会让它重写这一版」。写死成「打回」= 系统在向运营
**承诺一件它不会做的事**。

### 9.2 按下之后到下一轮之间，运营看到什么

1. `reply` 的响应回来时 `status` 已经是 `running`（`reply()` **先把 job 从「停住」挪开再交下去**）——
   页面**立刻**：禁用按钮、清空输入、显示「收到你的话了，正在跑（真浏览器 + 模型）」+ **正在走的秒数**；
2. 卡片**灰掉但留在屏幕上**（清屏会让「它在跑」和「页面坏了」长得一样）；
3. 轮询继续。**时间线在跑的时候也在长**（§3.3）—— 这是「屏幕不会看起来冻住」的正解：
   **每几秒就该有新的一行**（它的话 / 它的动作 / 自测的第 N 遍 / 系统的解释）；
4. 出现下列任一 → 恢复正常：事件多了、轮次多了、`status` 变 `done`/`failed`、`queued`（明说排队）；
5. **超时兜底**：同一个 `status="running"` 连续 `N` 分钟（默认 10）没有任何**新事件** →
   页面加一行**不吓人但诚实**的话：「已经 X 分钟没有任何新动静。可能是在真浏览器里慢慢走
   （自测那一轮最长），也可能是窗口没了 —— 你可以按「停」，或者去看一眼活窗口（**但别动手**）。」
   **不许**自动重试、**不许**自动再发一次 reply（那会把一句话落到下一道闸上）。
6. `409`（没在等人 / 窗口死了 / 别人已经回过话）→ **原样显示 detail 那段人话** + 重新拉 `/live`。
   窗口死的那条会带 `POST /job/{id}/reopen` 的命令 —— 这一片不做重开按钮（§十一），页面上明说「这条要人工执行」。

## 十、去看活窗口：一条几乎免费的入口

窗口是真的、跑在 worker 上；而**服务手上本来就有它**（`bit_window_from_env()` 从 `BIT_WORKER_IP` /
`BIT_ID` 建，`BIT_API_PORT` 默认 54345）。页面最下面一块：

```
这个窗口：  worker 192.168.1.222 ·  窗口 id 8f2c1a…  ·  Bit 的控制口 54345
怎么看：    连到那台 worker 的桌面（远程桌面 / 那台机器上的 BitBrowser 客户端），
            在 BitBrowser 里打开这个 id 的窗口 —— 就是 agent 正在用的这个浏览器。
            连得上就**看得见、也能直接接管**（鼠标键盘）。
⚠️ 它正在跑的时候**不要动手**；停在闸上动手之后，用「说一句」告诉我你动过。
```

**只摆「事实 + 方法」，不编 URL**：

| 说法 | 状态 |
|---|---|
| Bit 的窗口 API 是 `POST http://<worker>:54345/browser/...`（`BitWindow` 用的 `/browser/detail`、`/browser/update`、`/browser/pids/alive` 就在上面） | ✅ **核实过** |
| 「Bit 有一个**能远程用的网页控制台 URL**」 | ⚠️ **猜测，本次没核实**。仓库里没有证据；**别编一个 URL 摆上去**。**定它的办法**：问运营平时手动是怎么开/看一个窗口的（R-41 里他们用的是 `bit.sh`），或查 worker 上那个 BitBrowser 客户端版本的控制台/远程文档 |
| worker 有没有远程桌面、怎么连 | ⚠️ **运维知识，不在这个仓库里**。页面只给 worker IP + 一句话（「要连到那台机器上」），**不假装服务能代看** |
| 这个部署有没有窗口层 | ✅ 能判：`bit_window_from_env()` 给 `None` 时，这一块**明说**「这个部署没接窗口层，看不到活窗口」 |

**接管窗口安全吗 —— 分两种时刻，这张表要原样上页面**：

| 时刻 | 人接管会怎样 |
|---|---|
| **`waiting`（停在闸上）** | **图没在动**，接管不会跟 agent 打架 —— 这是唯一适合动手的时刻。但**你动过页面之后**，下一步就是在**你留下的那个页面**上跑的：探路会重新 observe（多半没事）；**自测**会拿着一个被人动过的页面跑，于是**报告会把「找不到元素 / 页面不对」记成产物的问题**（最贵的谎）。所以：接管之后用「说一句」把这件事告诉图 |
| **`running`（正在跑）** | **不要接管**：agent 正在同一个窗口里点、填、滚，两边的鼠标会打架 —— 动作会落到别处，失败会被记成产物的问题。**看一眼可以，动手等它停下** |

另外两条：窗口只活几分钟（P6），**去接管不会让它活更久**；把窗口**关掉** = 这一趟的窗口没了，
图会停在「自测那一步没有窗口（`no_window`）」——**那是一条正常的路**（`reopen` 能接住），不是 bug。

## 十一、这一片故意不做（免得被读成疏漏）

| 不做 | 为什么现在不做 |
|---|---|
| **中途停「别的」节点** | 要先把 `draft`/`lint`/`selftest`/`deliver` 改成可中断的（自测那五遍现在共用一个子进程循环，只有「整段跑完」一个出口）。能做，是另一片；**替代品**是「跑完这一步它一定会停在下一个闸口」（§四.1 第二行） |
| **停下之后接着走**（`paused` 续跑） | 探路一停，账本已经不完整，「接着走」= 「重探一遍」；而 `reopen` 接得住的那两支里没有 `paused`。**替代品**：`/again`（同一份开场白 + 你说过的话，重新发起） |
| **框选元素**（在图上点元素 = 选中选择器） | 规格 §6.6 明列在完整 Console；且依赖两件没解决的事：子帧 bbox 与主视口不是一个坐标系（R23）、DPR 那一轴（R22b）。**没解决就做，是做一个会错位的框** |
| **patch 预览 / py diff** | 规格 §6.6 的第 ③ 件。**更要命的实情**：默认接线里 `Deps.write` 是**恒等**的确定性翻译 —— **没有任何一双手能改产物**。所以「打回带话」今天**不会**产出一个改好的 py：那条回路会走到上限然后诚实停下 |
| **记忆层 / Correction Event 沉淀** | §6.5 是完整 Console 的验收；本片里运营说的话进 `hints`/`revisions`（在 checkpoint 里存着），但没有任何东西把它挖成规则 |
| **多用户 / 鉴权** | 没有身份：`revisions` 里没有「谁」；两个运营开同一个 job，后回话的会拿到 409（`reply` 已经这么做）。**内网部署的假设**，不是本片能解的 |
| **把活窗口内嵌进页面**（VNC / websocket 转发） | 那是**新的服务 + 新端口 + 鉴权 + 「谁在看」**。本片只摆事实 + 方法（§十） |
| **跨趟的对话历史** | 时间线是**一趟一份**（`Job.events`）；跨趟的连续性要真做记忆层才成立。`/again` 只带「同一份开场白 + 你说过的话」 |
| **在页面上提单** | `POST /run` 要的那几样（`success_text`、`goal`、`allow_skips`、`set_viewport`）是**教意图**的结构化输入，规格 §6.1 把它放在完整 Console 的输入闸门上。这一片的入口是**别人已经提交的运行**；`/again` 只是把**同一份**开场白再来一遍，**不教新意图** |
| **喊停以外的「重启/重开窗口」按钮** | `reopen` 要**一个新的 `ws_url`**（`bit.sh open` 吐的），那是宿主侧一条命令 —— 页面给不出，给个假输入框更糟。页面上把命令写出来，明说「要人工执行」 |
| **给它看图的对话**（把截图发回模型） | D12 的 `vision.inspect` 是另一条线；本片只把图**给人看** |
| **产物的 `--shots all`** | 产物自测仍用它自己的 `--shots failed`；本片不改产物 CLI |
| **清理磁盘** | 一次运行的图有上限（§5.5）；`runtime/` 不进 git，宿主要有清理策略 —— 记在风险里 |
| **时间线持久化** | 理由是高频 + 只有人看（§三.5）；真要持久就落 trace 或一张 append-only 表 |

## 十二、验收（用运营自己的话写）

**A1（本片的验收）**：一个人坐在屏幕前，**自己**一趟一趟在闸上回话，盯完一趟真运行 ——
全程能随口回答四个问题：**① 它现在在干什么？② 为什么？③ 我刚打的那句话去哪了？④ 我按停会怎样？**
并且**没有任何一件事是「发生了但没人说」**。

| # | 检查 | 反例（必须红） |
|---|---|---|
| A1 | 上面那句 | 有任何一个「它已经知道但没人说」的事实 → 不通过（具体见 A11） |
| A2 | 正在跑的探路里，**每几秒就有新的一行**（它的动作 / 它的话） | 屏幕静止超过 ~1 分钟而没有任何一行 → 不通过 |
| A3 | 在探路里说一句「不是那个按钮」→ **它的下一轮话里看得出它收到了**（时间线上有「已经交给它了」+ 它的回应） | 那句话只出现在输入框里、没进它眼前 → 不通过 |
| A4 | 按「停下，我要说一句」→ **立刻**有反馈，且**说清落点**（探路里几秒内 / 别的步骤跑完这一步） | 按钮按下去毫无反应、或只说「正在停止…」不说落在哪 → 不通过 |
| A5 | 在非探路的节点里按停 → 页面明说「它做完这一步一定会停下来问你，**你什么都不用按**」 | 让人以为停不下来而反复按 → 不通过 |
| A6 | 一对图**并排**看得出「点之前 / 点之后」，**一眼**看得出页面动没动 | 要放大、要开别的工具才看得出 → 不通过 |
| A7 | 没拍到图时，页面上写着**为什么**；随后补拍的那张有「随后确认时补拍」 | 空图框、或「图片加载失败」→ 不通过 |
| A8 | 点「继续」之后：按钮禁用 + 秒数 + **时间线继续长** | 停在旧卡片上假装还能点；或整屏静止 → 不通过 |
| A9 | 点「说一句」+ 一句话 → 下一轮里能看到**他那句话**（`who: "you"`）+ 它去哪了 | 那句话消失了 → 不通过 |
| A10 | 页面上能找到**这个运行用的是哪个窗口**，且**一看就懂怎么连上去看**；没接窗口层时**明说**；「跑的时候不要动手 / 停下动手之后要说一句」**在页面上** | 只有一串 IP 没有方法；或空白；或那张表只在文档里 → 不通过 |
| **A11** | **「没有静默」的机械检查**：把这一趟跑出来的事件按 `kind` 数一遍，逐条对上 §3.2 的目录表 —— 该有的都有（窗口死/重开、每遍自测、跳过与原因、上限、探针失败、图缺失） | 任何一条事实只活在日志/异常/某个 `why` 字段里 → 不通过 |
| A12 | 整条链上**没有**任何一处让运营需要读 JSON / 选择器 / 日志；页面**没有任何外部资源** | 卡片里出现 `#submit1`；页面里出现 `https://` 的 `src`/`href` → 不通过 |

**A1 是本片的验收**；A2–A12 是它站得住的前提（少一条，A1 就退化成「能不能跑起来」）。
验收的具体做法（含变异检查）在计划的 Task 10。

## 十五、产物交付：把跑出来的 py 交到人手上

> **2026-09-16 用户新增**。原话：「就是生成的 py 脚本也能下载啥的」。

### 15.1 为什么这条必须补上

这一片的其余部分都在讲**过程**（看它跑、跟它说话、喊停）。但**那套东西的目的就是产出一个 py** ——
而在原规格里，运营**唯一**拿到产物的方式是**去文件系统里捞**：
`out_dir` 是服务端的一个路径（`forms/sites/`），页面上一个字都没提。

**这跟 §1.3 的验收精神是冲突的**：验收要求「没有任何一件事是发生了但没人说」——
产出**本身就是**那件最重要的事，现在恰恰是「发生了，但页面不说、也拿不到」。

**所以这不是加功能，是把这一片自己漏掉的一段补上。**

### 15.2 交付什么、什么时候

- **交付的是 `deliver` 那一步真正写下的那个文件**（`.py`），不是「应该会写在哪」。
  **路径必须来自这一趟运行自己的记录**，不许页面自己拼。
- **没有产物时，页面必须明说没有** —— 这一趟跑到上限、窗口死了、或诚实停下，
  都要有一句人话（「这一趟没有产出 py，因为……」）。**不许摆一个空按钮或灰按钮了事。**
  这是本仓一整天在治的同一个病：**沉默的失败**。
- 顺带把**它写到哪了**显示出来（路径），人要对得上账。

### 15.3 端点（加进 §8.1 那张表）

```
GET /job/{id}/artifact
   有产物 → 200，body 是那个 py 的字节；
            Content-Disposition: attachment; filename="<site>.py"
   没产物 → 409 + 一句人话（说清为什么没有）
```

**安全边界（照做，别简化）**：
- **只许服务这一趟运行自己记录的那个路径**。不许接受调用方传路径 ——
  一旦接受，就是一个任意文件读取。**不接受任何路径参数。**
- 服务前**核对真实路径落在 `out_dir` 之内**（解析符号链接之后），否则拒绝。

### 15.4 页面上长什么样

- 时间线上，「它写下了 py」那一步**自带一个下载**（就是这一步的产物，不是一个全局按钮）。
- **在产物出现之前，那个位置不存在** —— 不是「灰着的按钮」，是**还没有**。
  出现了就是真的能下，这是本仓「接上了就要响」的同一条纪律。
- **明确不做**：在线编辑 py、在线 diff（都已在 §1.2 / §十一 划掉，别顺手加回来）。

### 15.5 验收（补进 §十二）

- **A13**：一趟**真的产出了 py** 的运行跑完之后，运营**只靠页面**就能把那个文件拿到手上，
  打开是能跑的那个 py（不是空文件、不是 404、不是一段 JSON）。
- **A14**：一趟**没有产出**的运行（例如跑到上限），页面**明确说出没有产出以及为什么** ——
  **不许**出现一个点了没反应或者下下来一个空文件的下载。
- **A15**：产物是**这一趟**的。跑两趟之后下载到的必须是**对应那一趟**的那个文件
  （这条最容易在「按站点名存一个文件」的实现里悄悄错掉）。
