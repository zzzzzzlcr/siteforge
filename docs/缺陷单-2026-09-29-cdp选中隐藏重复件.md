# 缺陷单（2026-09-29）：`cdp` 选中「不可见的同名重复件」⇒ 20 轮空跑 + 手势方向反转（并在放宽超时后变成**假成功**）

**给谁**：cdp 那条线（`/company/cdpcli`：`internal/shadow.go` 的选择器助手 + `internal/client.go` 的滚动/点击）
**严重度**：高 —— 与《缺陷单-2026-09-29-cdp滚动卡死》同族（同一段循环），但**机理不同、后果更坏**（假成功）
**状态**：cdp 侧未修；我们这边有候选规避（换选择器，文末）

## 现象（生产）

afrotech 那一单（任务 `26238922`，09-29 14:16）：

```
第 1 步 滚进视口     ✔（38 秒）
第 2 步 填 email     ✔（12 秒）
第 3 步 cdp click 'button[aria-label="Subscribe to Newsletter"]'
        → TimeoutExpired: timed out after 30 seconds   ⇒ 整单 exit=unknown
```

第 3 步要点的按钮**在页面里、而且就在视口里**（实测 `ratio:1`），却烧掉 35 秒没点成。

## 根因（代码级，三条叠起来）

```
internal/shadow.go:38   __cdpQIn(root, sel)：__cdpRoots 里逐个 root 取 **querySelector 的第一个匹配**
                        —— 只讲文档顺序，**不讲可见性、不讲尺寸**
internal/client.go:875  IsElementVisible：
                          visibleArea = (min(right,vw)-max(left,0)) * (min(bottom,vh)-max(top,0))
                          totalArea   = width * height
                          return visibleArea/totalArea >= 0.8
                        ⇒ 元素 0×0 时 totalArea=0 ⇒ **0/0 = NaN** ⇒ `NaN >= 0.8` 恒 false
                          （另外这个算式对"在视口外"的矩形**不做 clamp**，会算出负数 —— 结论一样是 false）
internal/client.go:1100 ScrollToElement：for i<20 { ScrollTouch(); if IsElementVisible() break }
internal/client.go:946  ScrollTouch：方向靠 `isAbove := centerY < vpHeight/2` 判
                        ⇒ 隐藏件的 centerY = 0 ⇒ **永远"在屏幕上方"** ⇒ 每轮都是下滑手势
                        ⇒ 页面被**往上**拖，元素越离越远 ⇒ 20 轮**结构上不可能收敛**
internal/client.go:886  ScrollIntoView：`__cdpQ` 打的还是**同一个隐藏节点** ⇒ scrollIntoView 空操作
internal/client.go:1169 ClickElement 末尾：GetElementCenter → (0,0) ⇒ 点 (0,0)+高斯偏移
```

**后果分两档**：

- 调用方上限 30 秒（现状）⇒ `TimeoutExpired`、整单炸（**响的失败**）；
- 上限放宽到 60 秒（我们 09-29 的止血）⇒ 20 轮跑完、点**页面左上角**、回执里 `x/y/match_count` 一切正常
  ⇒ **假成功**（不报错、不重试、日志好看）。**比超时更坏。**

## 建议修法（按性价比）

1. **可见优先的解析**（真修，一处，全站受益）：`__cdpQ` 的调用方（click / form / check / select / scroll）在拿到匹配后
   **先挑第一个"可见"的**（`offsetParent != null` 且 `width*height > 0` 且比例 > 0），都没有再退回第一个。
   或者给助手加 `__cdpQVisible(sel)`（先 `__cdpQAIn` 收全部，再挑）。
2. **判据要 clamp + 面积 0 要明说**：`Math.max(0, …)`，并且 `totalArea === 0` 直接判「不可用」而不是落进 NaN。
3. **失败要说人话**（和另一张单子的第 3 条同）：把「选中了 0×0 的隐藏件；同选择器还有 N 个候选：各自的 rect/在不在 footer」写进错误/回执。
   现在超时那一刻**一个字段都没有**。
4. **方向别用 centerY=0 猜**：元素不可见时先做一次精确 `scrollIntoView`（或先量"它离视口几屏"）再决定滑动方向，
   否则"隐藏件在 (0,0)"这个特例会把手势系统性地带反。

## 附：同一页面上还有第二件事（已单列，供交叉参考）

长滚之后**有时**会冒出 Quantcast 的同意弹层：

```
DIV.qc-cmp-cleanslate   position:fixed  z-index=2147483647  rect=[0,0,375,812]   ← 盖住整个视口
  BUTTON#accept-btn     "AGREE"    rect=[22,521,345,37]
  BUTTON#disagree-btn   "DISAGREE" rect=[22,630,345,39]
手势起点（上滑 x≈0.75vw）：281,808 / 281,792 / 281,752  →  全被这个 DIV 吃掉
（它还把页面 shadow root 从 2 个变成 45 个）
```

⇒ 它**会吃掉 `ScrollTouch` 的触摸**（起点就在视口最底那条，正是弹层最爱待的地方），
并且给"同名重复件"这类问题再加一层噪音。**它不是本次 46.9 秒的主因**
（那一窗弹层不在场，照样 46.9 秒），但它必须是产物/骨架里"动手前先清障"的一环
（新骨架有同意弹层钩子，afrotech 这份产物没有覆盖 Quantcast）。
