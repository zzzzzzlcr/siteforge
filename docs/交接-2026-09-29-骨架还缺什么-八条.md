## 1. 判据只在"生成那一刻、那一份页面"上验过 —— 要**两向**、要**复验**

**现状（读代码量的）**：`agent/browser_agent.py:712 when_holds()` 确实会在生成时验一遍
（`:3254` 调用），但它只回答"在这份页面模型上成不成立"，而且：

* 空 `when`、或只有 `url_contains` 而没有 `text_contains` 的，**直接返回 True**（`:719`、`:727`）；
* `text_contains` 判的是**整页拼接后的大字符串**（`_norm(model["page_text"])`）——
  判据可以是**跨两个元素的拼接子串**，生成时成立、重放时因为版式不同而永不成立；
* **反例方向（"在别的页面上不成立"）从来没验过** —— 而这正是"整组静默跳过"的来源；
* ★ 更要紧的一条：**判据本身是从这一页的 `page_text` 里取的原文字串**，所以"生成时验一遍"
  是**循环论证** —— 代码注释里就是这么写的（`browser_agent.py:4210 _snippet()` 上面那段：
  「正文那一段是从这一页的 `page_text` 里**取的原文** —— 它是当时那一页的**子串**，
  所以必然成立」）。**它必然成立，恰恰意味着这一验什么也没验**；
* 生成之后**再没人复验**：站点改一次版式，判据就一直不成立，日志里只有一行 INFO 跳过。

**今天的代价**：georgiapower「真做 2 步、跳过 23 步，每一步日志都写着点上了」；
travelandleisure 那 18 条卡在 `go-offer-enter` 的 `when` 上（它要横幅正文，而横幅是晚出现的）。

**要补的**：
1. 生成期**两向验**：拿真页面验正例成立 **+** 拿**另一个页面模型**（同站别的步骤 / 上一次抓的）验反例不成立；
2. 判据必须是**单个元素内**的子串（`_snippet()` 那一格已经在做逐元素读口）；
3. 产物侧加一条"判据连续 N 组不成立就喊"（骨架已有 `SKIPPED_GROUPS_ALOUD`，但那是**跑的时候**喊，
   生成期就该拦住）。

## 2. 产物与骨架之间没有版本契约

**现状**：产物里记了 `PROVENANCE`（`generated_at` / `generator` / `source.runtime` 指纹），
但**没有"骨架版本"这一格**。于是"线上这份产物比仓库里的骨架落后多少"没人答得上来。

**今天的代价**：重渲一版 travelandleisure，**一口气多带了 8 个方法**
（`_follow_new_tab` / `_ALIASES` / `_page_trouble` / `elementsFromPoint` 那批 09-28 的活儿）
—— 也就是说旧产物在线上继续跑、骨架在仓库里往前走，中间没有对账。

**要补的**：
1. 产物里记**骨架指纹**（`SKELETON` 的 sha256 或版本号），与模板一起进 CI 校验；
2. 一条"这个产物落后骨架几个改动"的体检（重渲不再靠人记）；
3. 生成器**默认**用当前骨架 —— 不要留"上次渲染的那份"在线上无声地跑。

## 3. 同一个守卫在三处各写一遍 —— "落点是不是它"该**下沉到 cdp**

**现状**："这一下点下去，那个坐标上画的到底是不是我要点的东西"这件事，今天在三处各实现了一次，
措辞还不一样：

| 位置 | 形态 |
|---|---|
| `forms/sites/warthunder.py::_check_eula_once`（手写 py） | `elementFromPoint` 落点守卫 + 元素自身 `click()` 优先 |
| `form_executor/json_executor.py::_smart_form`（JSON 线） | `elementFromPoint` 守卫（`skipping coord-click`） |
| `agent/template.py::_cover_once` / `_covered_by`（骨架） | `elementsFromPoint` 整摞、跳过 `pointer-events:none` |

三处规则**不一致**（单点 vs 整摞、要不要跳透明层），于是"同一张页面在三条线上行为不同"。

**要补的**：把它做成 **cdp 二进制的一格**（`internal/form.go::CheckElement` 已经有一半）：
**任何坐标点击之前，先问一次落点是不是目标（或其后代/其 label）**，不是就拒点并说明理由。
做在那儿，三条线（手写 py / JSON / 骨架）自动都有，也不用每站再抄一遍。
⚠️ 前置：**部署的那份 cdp 源码不在手边**（`git log --all -S'--strict'` 全历史零结果，
而线上二进制里 `strings | grep expect-label` 有 3 处）—— 这条不解决，下沉无处可落。

## 4. 失败现场是**抽样**的

**现状**：解释一次失败最值钱的三样 —— **截图**、**点到的其实是谁**（`at_point`）、
**这一页是不是风控/空白页** —— 生产那条线上**默认都不采**：
骨架的现场探针（`_SCENE_JS`，`template.py:649`）只在 `--trace` 打开时跑，
而生产重跑是"不截图、不 observe、不落 trace"（`template.py:2893`）的便宜路径。

**今天的代价**：funchatt 今天 7 条失败，**一条现场都拿不到**（`failDiag` 全表 100 条里 0 条）；
warthunder 那三条能查清，纯粹是因为 `fail_img` 有截图 —— 一眼看出"人已经站在法律页上了"。
另外 `failDiag` 只有部分机器上报（memory `faildiag-fleet-gap`：全表 3 行全是同一台）。

**要补的**：
1. **失败那一步**无条件跑一次现场探针（一次 eval，给全四样），随日志一起上报；
2. 上报通道覆盖全舰队（不是"哪台装了 token 哪台有"）；
3. 现场里加上"这一页的**整页正文前 N 字**"与"**活跃页地址**" —— 今天两次都是靠这两样定的案。

## 7. 动手之前只问了"整页"，没问"这一下真的点得到吗"（2026-09-29 开窗实测）

**现状**：`_perform()` 动手前只有一道 `_page_ready` —— 它问的是「**有没有一整块 loader 蒙版盖着整页**」。
页面**正在下载 / 首屏还没渲染**（没有蒙版）时它返回空串 = **放行**。而"这个元素现在
`elementFromPoint` 命中它自己吗"这一问，只在 `_cover_once` 里、且**点之后**才量（trace 才有）。

**实测**（georgiapower 落地页，**真广告 URL**，375×812，走的就是产物那条 `cdp click` 路径；
只点、不填、不提交）：

| 点击那一刻 | 结果 |
|---|---|
| `readyState=loading`、正文 0 字 | **点了个空气**：60 秒内新 tab 从没出现、地址一直是落地页；而 **cdp 回执一切正常**（`match_count:1`、坐标正常，只有 `landing_blind`） |
| `readyState=interactive`、正文 2619 字 | **+2.26 秒**新 tab 出现 → **+4.3 秒**地址变成目标页 |

四次采样：interactive 时点 **2/2 成**，loading 时点 **2/2 不成**。而那个 CTA 是
`<a target="_blank" href="…/GPClipboardAuditScheduler">`：首屏 **~10 秒**才 interactive，
runner 导航到产物第一击只有 **~6 秒** ⇒ **正好压在成/不成那条线上** —— 这就是"时好时坏"。

**要补的**：动手前把"点得到"做成**硬判据**：`readyState != 'loading'` **且**
元素中心 `elementFromPoint` 命中它自己 / 其后代（`label` 包 `input` 那类算同一个东西）；
不满足就**有界等**，等不到**如实说"没动手"**，别把那一下发出去。

## 8. 点完不复核、也不重试 —— 重跑路径上"点了没反应"是隐形的（2026-09-29 开窗实测）

**现状**：`_follow_new_tab` 在 `cdp click` 返回后**立刻**看一次 `/json/list`；实测那时候
**一定没有新 tab**（弹窗 **2.26 秒**才出现，而且**先以空地址出现**，**4.3 秒**才有地址）。
每个状态判据不成立时还有一次 `_follow_tab_matching`，但它只认**地址里已经含目标**的 tab
—— 空地址那 2 秒认不出来。

更要紧的是：**重跑路径不算 progress**（`_run_step` 里 `if self.tracing:` 才做快照 / diff），
于是「点了但页面什么都没动」与「点成了」**长得一模一样**；`stalled`（连着几步点了页面都没动
就收摊）那条刹车**在生产永远不会触发**。生产 `26233250` / `26226785` 就是这么跑完 2 分钟、
20 步全跳过，而每一步日志都写着"点上了"。

**要补的**：
1. click 之后在 **5 秒窗口里轮询**三种证据之一：地址变了 / 多了新 tab / 整页正文变了；
   没变就**重来那一击**（重试前先过 §7 那条闸）；
2. 这一条**必须在重跑路径上也有** —— 今天唯一没有它的路径就是重跑；
3. `landing_blind`（`cdp click` 回执里"落点判据没跑成"）现在只是被贴进 note。它恰恰是
   "这一击可能点空了"的**先兆**（生产日志里那句「这一帧的落点判据用不了：跨站子帧里它不触发」
   是**同一个字段的另一种文案**）—— 要么修好它，要么它出现时按"**没验成**"处理。

**量具**（可直接复用，只点、不提交）：`docs/probes/2026-09-29-georgiapower-click/gp_probe.py`
（命中几个元素 + 回执原文）与同目录 `gp_probe2.py`（点后 60 秒逐秒的 tab 时间轴 + 会话当前页）。
两条都要先从 failDiag 现场里抠出**那条真广告 URL**（我那份落在 `/tmp/gp_faildiag.json`）。
