## 二、根因

`_matches` 对 `text_contains` 的判法是**不分大小写的子串包含**：

```python
wants = when.get("text_contains") or []
if wants:
    signature = self.page_signature().lower()
    if not any(_norm(str(w)).lower() in signature for w in wants):
        return False
```

而原件那 11 条判据，**是生成期从一次观测里剪下来的一段连续子串** ——
剪点落在**两个不相邻的元素中间**。三类病灶：

| 类型 | 原件判据 | 为什么真站上不成立 |
|---|---|---|
| **跨元素剪接** | `Main Content Schedule your residential` | 是 `Skip to Main Content`（a11y skip-link）的**尾巴**接上主标题开头拼出来的。真站实测页面以 `Schedule your residential clipboard…` 开头，**前面没有那句 skip-link** |
| **瞬时状态** | `Please enter a valid email address in the`<br>`Street Complete this field.` | 这是**校验报错**文案 —— 只有空提交 / 非法值那一刻才出现 |
| **依赖填值** | `123 Peachtree St NE Atlanta, GA, USA 123` | 是「下拉候选 + 输入框里的值」拼的。而 `FILLS['postcode']` 用的是随机池 ⇒ **判据与我们填什么自相矛盾** |

**放大器（这条同样重要）**：11 组的 `url_contains` **完全相同** ——
Salesforce 向导是 SPA，**URL 全程不变**，认页**全靠正文**。
⇒ 第一条（也是漏斗第一组）垮掉，**后面 10 组连锁静默跳过**。

## 五、为什么自测 / 账本没能提前拦住

1. **账本只存正文的哈希，不存原文**。`journey.steps[].sig_after` 长这样：
   `{'url': '…', 'text': 'c905e5e95dec', 'visible': 15}` ——
   **判据当初是从哪段正文剪出来的，事后无法复盘**。这一条直接决定了「这类 bug 只能靠开真窗抓」。
2. **这份产物是「就地重渲」的**：`PROVENANCE` 里
   `generated_at / generator / env / platform / selftest` **全是 `None`**，
   只有 `from: 就地重渲（人点名修两处）` ⇒ 「自测过了」这句话在这份产物上**无从谈起**。
3. **合成页 A/B 通过 ≠ 真站通过**：那次 A/B 的合成页里 CTA 是**主帧**里的 `<a target=_blank>`，
   而真站的 CTA 在**跨站子帧**里（note 原文：「这一帧的落点判据用不了：跨站子帧里它不触发」）。

## 六、改哪里 —— 代码级指引（这一节是给动手的人）

### 6.1 病灶点：`agent/browser_agent.py:4091` `_snippet()`

判据就是**这一处**剪出来的，两个调用点：
`_when_for()`（`:4030`，生成期）/ `_when_from_row()`（`:3340`，重放期）。

```python
head = text[:WHEN_SNIPPET_CHARS]        # 从**拼平的整页正文**里取开头那一段
```

它剪的是 `_norm(model.get("page_text"))` —— 而 `page_text` 是 `cdp observe` 把
**整页（含各 shadow root）的 `innerText` 拼成的一个字符串**，**元素边界已经没了**。
⇒ 剪出来的那一段**天然可能横跨两个元素**：本次那条 `Main Content Schedule your residential`
正是「`Skip to Main Content` 的尾巴 + 主标题的开头」。

### 6.2 为什么现有的闸拦不住（这点很关键）

`when_holds()`（`:632`）的验证是「这段是不是 `page_text` 的子串」——
而 `_snippet` **就是从 `page_text` 剪的** ⇒ **必然成立**（该函数 docstring 自己也写着「所以必然成立」）
⇒ 这道闸对「跨元素」这个病**恒真**，等于没有。

### 6.3 三个改法（按彻底程度排）

**① 治本：判据从「单个元素的文本」取，不从拼平的 `page_text` 剪**

`observe` 的模型里**本来就有元素表** —— 今天实测的原样输出见
`docs/probes/2026-09-28-georgiapower/地址屏-observe-真实字段.json`，
`fields` / `actions` 里每一项都带 `label` / `text`。

判据改成：**挑一个「该页独有」（`avoid` 里没有）且「非瞬时」（不含报错词）的元素，
取它自己的文本**。这样天然不跨元素，而且鉴别力比"正文前 N 字"强。

**② 治标（最便宜、不依赖元素表）：给 `_snippet` 加一道跨元素校验**

让 `observe` 的模型多存一格「每个文本节点的片段」（例如 `text_nodes: [str, …]`），
`_snippet` 剪完之后：

```python
if not any(head in n for n in (model.get("text_nodes") or [])):
    return ""          # 跨了节点 ⇒ 不剪
```

⚠️ 退回「只有 URL」是**有损**的 —— 按本项目规矩必须**说出来**（`WHEN_TEXT_DROPPED` 那一套已经有了，
直接复用；**不许**静默退化）。

**③ 防复发：产物 lint 三条**（生成完 / 上传前跑一遍，命中就报警）

| 检查 | 怎么判 |
|---|---|
| 判据跨元素 | 见 ② —— 对**产物里已有的** `when` 也能跑（拿判据串去元素表里找归属） |
| 判据是瞬时状态 | 命中 `error\|invalid\|complete this field\|please enter\|required` ⇒ 报警 |
| 判据含「我们填进去的值」 | 与 `FILLS[*].fallback` 里的字面量求交，非空 ⇒ 报警 |

### 6.4 另外三处（骨架，改动量都很小）

| 位置 | 改什么 |
|---|---|
| `agent/template.py:776`（`_PAGE_TEXT_JS`） | `"try{parts.push(c.innerText\|\|c.textContent\|\|'');}catch(e){}"` —— `<style>` 的 `innerText` 是空串 ⇒ 回退 `textContent` ⇒ **CSS 整段灌进「正文」**。先滤掉 `style/script/template` |
| `agent/template.py:707` / `:711` | `POSTCODES` / `PHONES` 是**英国**格式，填进了美国站。按国家分池（`FILLS` 里 `country` 那一格已经知道该填哪个国家了） |
| `agent/template.py:2318`（`_matches`） | 加一格 `element_exists` —— SPA 站 URL 全程不变时，**结构性判据是唯一稳的一侧**。`_last_model`（`observe` 的模型）里本来就有元素表，不必新起 cdp 调用 |

## 七、建议的修法（按性价比排序）

> 每一条「改哪里」的**具体文件 / 函数 / 行号**在第六节；这一节讲**改什么**。

### A. 判据形态 —— 硬约束 + lint（**最高优先**）

1. **判据必须来自单个元素**（一个标题 / 一个标签 / 一个按钮），
   **禁止**把页面正文剪一段当判据 —— 这是本缺陷单的正题。
2. **禁用瞬时状态**：错误提示、toast、loading 文案，一律不许进 `when`。
   建议 lint：判据串命中 `error|invalid|complete this field|please enter|required` 等词 ⇒ 报警。
3. **禁用随填值变化的文字**：判据不许包含将要填进去的值（地址、邮编、邮箱…）。
   lint：把 `FILLS[*].fallback` 里的字面量拿去和 `when.text_contains` 求交 ⇒ 非空报警。
4. **跨元素剪接的机械判据**：判据串若**不是**页面上任何**单个**文本节点的子串 ⇒ 报警。
   （探索期就能算：剪之前先看这段落在哪个 node 上，跨 node 就别剪。）
5. **SPA 站在 URL 不变时的兜底**：给 `when` 加 **`element_exists`**（见 6.3 与 6.4）。

### B. 给 `when` 加一格 `element_exists`（结构性判据）

这站的 `name` 属性是业务名、**比行文稳得多**：
`input[name="How_many_people_live_in_your_home"]`、`select[name="country"]`。
`_matches` 里作为 `url_contains` 之外的另一条 **AND** 判据即可。
实现上**不必新起 cdp 调用**：`_last_model`（`cdp observe` 的模型）里本来就有元素表。

### C. 选择器优先级（生成期排序）

`aria-label` / `name` / `role`+text **排第一**；框架自造的 `#input-NN`、`nth-of-type` 长链
**只能当兜底**，不许放首位。（同一天实测：稳的全中、漂的全是自造 id；逐条对照见第四节 1。）

### D. 骨架

- `_PAGE_TEXT_JS` 对 shadow root 的子节点用 `innerText || textContent` —— `<style>` 的
  `innerText` 为空 ⇒ 回退到 `textContent` ⇒ **把 LWC 的 CSS 整段读进「正文」**
  （实测旁证：trace 里 `page_sig_tail` = `--mobileLanding-colorTextButtonBrand:rgb(255, 255, 255);…`）。
  600 字符的窗口被 CSS 挤爆 ⇒ shadow 里跳过 `style/script/template`。
- 随机池按国家分（见四.3）。

### E. 账本与自测（让下一个这类 bug 不用开真窗）

1. **账本里存判据那段正文的原文**（或至少存「判据落在第几个 node / 属于哪个元素」）。
2. **自测报告带环境指纹**（Bit 档案的 UA / DPR / 视口），不一致就当场说「这一趟不代表那个档案」。
3. 连续跳过 ≥N 步（`STUCK_LIMIT` 只管**失败**、不管**跳过**）就当场报警 ——
   「这一页一直不像任何状态」不该等到结账才说。
