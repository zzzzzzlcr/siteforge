# 交接：JSON 配置那条线（给来接手的人）

**状态（2026-09-21 后续）**：JSON 配置已从「**只读**」变成双阶段安全写回。
入口为 `POST /jsonwrite/prepare`（合规检查 + 真页面复跑，不写）和
`POST /jsonwrite/commit`（一次性票据确认写入）；写前重读防覆盖、写后回读核对，原件落本地备份。
`POST /jsonwrite/rollback` 可显式恢复。当前只更新已有配置，不开放未实测的创建分支。

【我量的·2026-09-21】真实写口使用表单编码，不是 JSON request body：`site`、JSON 字符串
`steps`、审计字段 `operator` 三格必填。对 `cvrefresh.com` 原样写回得到业务码 200，写前/写后
SHA-256 一致；用 JSON body 会得到业务码 400。客户端已按实测契约修正。

## 二、**没验**的（你要**先量**，再动手）

| 没量过的 | 为什么要紧 |
|---|---|
| `update_form_config` 的**「有就更新、没有就创建」**（upsert）到底成不成立 | 这是「新建一个 json 站」这条路的前提。**只有人这么说过，没有量过** |
| 写回**之后**执行器认不认（真跑一遍那个站） | 写回成功 ≠ 那个站在跑。判据是**执行器认** |
| 写回**再读回来**是不是同一份（往返一致） | 不一致就说明我们写的形状有偏差 —— 而它会**静默** |
| 写坏了怎么退（有没有回滚/备份） | 写错一个站的配置 = **那个站整站挂**，而且不是我们自己的站 |

⚠️ **写口是这仓里唯一会改外面世界状态的路**：读错了最多是结论错，写错了是**生产出事**。
所以顺序建议：**先读回来 → 本地校验 → 写 → 再读回来核对**，每一步都把话写清楚。

## 三、怎么跑、什么纪律

```bash
cd /company/siteforge
.venv/bin/python -m pytest tests/ -q        # 全绿：1332 passed / 12 skipped / 0 failed
```

- **测试集不许缩水**；改了既有断言要**逐行交代**（改了哪条、为什么、有没有放宽判据）。
- **秘密不进仓、不进对话**：token 从环境变量/文件读，别写进代码和文档。本仓已扫过一遍，
  被跟踪的文件里没有真凭据。
- 真值一律**现读现量**（`【我量的·…】` 那种注释就是给这个用的）；**「没量到」不许写成「没有」**。
- 这个仓最贵的一类 bug 是「把量不到读成没量到」：`200 + {"status":404}` 被读成「这个站没配置」，
  然后写回时把一份空配置盖上去 —— 这一类形状在 `fmr.py` 与 `ad-task.py` 里都有案底。
