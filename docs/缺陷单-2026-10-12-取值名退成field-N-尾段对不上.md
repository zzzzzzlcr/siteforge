# 缺陷单（2026-10-12）：取值名退成 `field-2`… —— **模型的写法与观测的写法尾巴一样、前缀不同**，于是身份全丢

**一句话**：产物里那几格的取值名（`FILLS[*].source`，**重放时拿去运营资料里找真数据的那把钥匙**）
退成了 `field` / `field-2` / … —— 因为 `_find_element` 认元素靠「选择器原样对上 / alternates /
`#id` ↔ hint」三档，而模型填那几格时写的是**同一个元素的另一种写法**：
`form:has(input[placeholder="A friend's code"]) > label:nth-of-type(7) > input`
而观测记的是 `body:… > label:nth-of-type(7) > input` —— **尾巴一模一样、前缀不同** ⇒ 三档全对不上
⇒ 那一格的 `label/hint/placeholder/nearby_text` **全丢** ⇒ 名字退成 `field-N`。

---

## 一、现场

| | |
|---|---|
| job | `job-bcb1863324f4`（8100 / 222，验证那一趟） |
| 站点 | `nitrouscompetitions.com/auth` 的注册屏 |
| 读数 | 产物 `FILLS` 键 = `field / field-2 / field-3 / field-4 / field-5 / field-6` ＋ `email / password / dob / phone` —— **后四个有名字、前六个没有**，而它们在同一张表单上 |

**为什么是「有些有、有些没有」**（这一条把根因指得很准）：

- `type=email` / `type=password` / `type=date` / `type=tel` 那几格有**唯一属性** ⇒ `observe` 给的
  选择器就长成 `form:has(…) input[type=email]` **原样**，模型照抄 ⇒ 第 0 档就对上 ✓；
- 地址 / 城市 / 邮编 / 下拉 / 两个勾选**没有 id、没有 name、type 又是 `text`** ⇒ `observe` 只能给
  **位置链**，而模型写的是它的 `:has()` 变体 ⇒ 三档全对不上 ✗。

## 二、量到的证据（真站，`_probe_observe_identity.py`）

**观测那一侧没问题** —— `cdp observe` 每一格都给了 label：

```
label='Full name'        sel=body:nth-of-type(1) > main:nth-of-type(1) > div:nth-of-type(1) > …
label='Address line 1'   sel=body:nth-of-type(1) > main:nth-of-type(1) > div:nth-of-type(1) > …
label='Town / City'      sel=body:nth-of-type(1) > main:nth-of-type(1) > div:nth-of-type(1) > …
label='I confirm I am 18 ' sel=body:…
label='How did you hear a' sel=body:…
```

而账本里那几格的 `target` 是 `label=None hint=None placeholder=None nearby_text=None` ⇒
**丢在「认元素」那一环**（`_find_element`），不在观测、也不在起名。

> 这是同一条毛病的第二次（第一次是 2026-10-08 的 laterlifechoices：模型写 `input#phone-3848a5d5`、
> 观测写 `input[placeholder="+44 0000 000000"]`，四格名字退成 `field`…）。当时的补丁是加了一档
> **`#id` ↔ hint**。这一单暴露的是它的邻居：**那几格连 `#id` 都没有**，那一档够不着。

## 三、后果（为什么值当一单）

`source` 就是重放时 `form_data[source]` 那把钥匙（`_ALIASES` 再兜一层）：

- 对不上 ⇒ **取不到运营资料**，值掉进随机池，而日志照样写「填好了」——**静默**；
- 探路那一趟真填进去的值还会被记成 fallback（真站实测过：手机号写死成同一个号，每条 lead 一样）。

## 四、已修（2026-10-12）

`agent/browser_agent.py`：

1. 新增 `_selector_tail(selector, n=2)`：选择器的**尾段**（按 `>` 切最后两段）；
2. `_find_element` 多一档（`rank 6/7`，排在「原样 / `#id`↔hint」之后）：
   **模型那根选择器的尾段在池子里唯一** ⇒ 认它那一格。

两条**不许破**的边界（与 `_id_is_the_elements_hint` 同一条纪律——认错比认不回来坏得多）：

- **尾段必须唯一**：池子里有两格尾巴一样 ⇒ **一条都不认**（退回「只有选择器」的形态）；
- **尾段要有鉴别力**：`nth-of-type(k)` / `#id` / `[attr=…]` 才算数 —— `div > input` 那种到处都有，
  不认（不然每一格都会被同一根尾巴认走）。

## 五、用例（先红后绿）

`tests/test_browser_agent.py::test_a_positional_selector_from_the_model_is_tied_by_its_unique_tail`：
照真形状造两格（`label:nth-of-type(3) > input` 与 `label:nth-of-type(7) > input`），模型给的是
`:has()` 变体 ⇒ 必须认到第 7 格；两条反例：尾巴一样 ⇒ 一条都不认、尾段无鉴别力 ⇒ 不认。
`tests/test_browser_agent.py` 全绿：**225 passed / 1 skipped**。

**真数据复验**：`runtime-222/_verify_tail_tie_real.py` —— 用真站抓下来的 observe 模型回放那一趟
每一步的起名（修前 `field-N` ⇒ 修后该是 `label` 有的语义名；地址那格该落到 `street`，
那是同一天 `_RANDOM_HINTS` 补了 `address` 之后的效果）。

## 六、还开着的

- 这一刀管的是**「观测给了身份、只是没接上」**。真正**观测里就没有身份**的那些格
  （页面上一个字都没有：既无 label 也无近旁文字）仍然只能退成占位名 —— 那是另一条线，
  `_fallback` 的「用账本里真填过的值」在那儿兜着（那条路的账在
  `docs/缺陷单-2026-09-28-*` 那一族里）。
- 名字落到语义名之后，**运营资料的列名**还得对得上（`_ALIASES` + 运行期 `library_key`）——
  那是**数据对齐**，不是这一单。
