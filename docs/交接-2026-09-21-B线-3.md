## 2. 两处修（一处是这一棒最重的）

### ① 榜单那一行不再说「有 py 脚本」

- **病**：后端那一格的判据是 `scriptKind() !== null` —— `script_source` 非空 ⇒ py、
  否则 `steps` 解得出非空数组 ⇒ json，**两种都算「有」**。而这一行说的是 **py**。
- 【我量的·2026-09-21】`cvrefresh.com`（**json 站**，`GET /configcheck?site=cvrefresh.com`
  回「这份配置执行器都认」）在榜单上的那一行当时写的是
  `失败 7 次 · 配置 34（启用） · 有 py 脚本` ⇒ 假话，两处口径当场对不上。
- **药**（`agent/fmr.py:753` `has_script_say`）：

  | 值 | 改前 | 改后 |
  |---|---|---|
  | `True` | 有 py 脚本 | **有脚本或配置** |
  | `False` | 有配置，可是没有脚本 | **有配置，可是里面是空的** |

  （`None` 那支不变；三态仍然是三句话、处置仍然相反。）
- **变异测试**：把字符串改回「有 py 脚本」⇒ **3 条用例红**
  （`test_a_rank_row_becomes_one_human_sentence`、`test_has_script_is_three_states_not_two`、
  `test_service_rank_diag.py::test_the_rank_comes_back_as_human_rows`）；
  只把 `False` 那一支改回去 ⇒ `test_has_script_is_three_states_not_two` 红。
- **在真面板上验过**：重启后 `GET /rank` 那 8 行全部写成「有脚本或配置」。

### ② 修站那条路在**面板的真实载荷**下 500（★ 这条最重）

- **病**：`agent/service.py:4330` 拿 `body["url"]` 去读**载荷对象** ——
  它是 **pydantic 模型，不可下标** ⇒ `TypeError` ⇒ **500**。
  它只在 `body.site` 为空时走到，而**面板 `runPayload()` 根本不发 `site`**
  （`agent/console.html:1469-1482`，只有 url / goal / success_text / mode / evidence /
  fix_site / fix_site_url 那七格）⇒ **面板上按「开一趟」修站，每一次都是 500**。
- **为什么一路没抓到**：`tests/test_service_fixsource.py` 的夹具 `_brief()` **一直塞着
  `"site": SITE`** —— 「面板的真实形状」那一格从来没被走过（**夹具与载荷不是一回事**）。
- **药**：`graph.site_name(getattr(body, "url", "") or "")`；
  新加用例 `test_the_draft_stages_when_the_page_sends_no_site_key`（就是面板那一份形状）。
- **变异测试**：改回 `body["url"]` ⇒ 那条用例红（`assert 500 == 202`）。
- **底稿这条路真打过枪**（打**线上**后端）：`lastingpowerofattorney.io/article-1` 落成
  `/tmp/fixstage2/lastingpowerofattorney.before.py`，**与后端逐字节一致**（22375 字节，
  `sha256 == 后端给的 sha256`）—— 用的是**改后**的代码、`site` **空着**（面板那样）。

## 3. ★ 挡在「真跑一遍修站」前面的一件事（**要用户定**）

上一棒留的那件事（挑一个「启用的、py 的、真在失败的」站真跑一趟）**挑好了**，
但**跑不了** —— 挡在门口，原因不是环境，是**形状**：

- 修站那条路要的底稿是**模板形**的 py：里面得能读出 `STATES = [...]` / `FILLS = {...}`
  （`agent/fix.py::from_py` → `_literals`）。
- 【我量的·2026-09-21】**线上那 13 份 py，一份都不是这个形状**：
  6 天榜单去重 **22 个站**（py 13 / json 3 / 读不到 6），`from_py()` 对**每一个 py** 都回
  `(None, None, ['这份 py 里的 STATES/FILLS 读不出来（坏 py 或动态构造）—— 修不了'])`。
- 线上那 13 个 py，逐个量过：

  ```
  lastingpowerofattorney.io/article-1      goldenagesouls.com/land/sp/9ae19fba
  goldenagesouls.com/land/sp/e7eacd5f      goldenagesouls.com/land/sp/949c33f8
  goldenagesouls.com/wizard                entyrecare.com/calculator/michigan
  callyourdate.com/land/sp/519015a5        juliettdate.com/land/sp/382c571c
  qualify.lastingpowerofattorney.io        offers.renewalbyandersenpros.com/form
  soulfuldate.com/land/sp/45c428a5         wallstwatchdogs.com/the-2-gold-miner-…
  ```

- 它长这样（`lastingpowerofattorney.io/article-1`，18936 字 / 22375 字节）：
  `class LpaFiller` + `SKIP_FIELDS` / `PRIMARY_BUTTONS` / `SUCCESS_URL_MARKERS` /
  「每轮读页面 → 有什么填什么 → 循环」，文件头自己写着**「读页面型，不是固定步骤表」**。
  ⚠️ 它**不是**步骤表 ⇒ 不是「解析器写窄了」，是**这一族脚本压根没有 states/fills 这回事**。

⇒ **今天没有任何一个线上 py 站能被这条路修**：它在 **intake** 就红（`END_…` + 一句人话
「修不了：这份 py 里的 STATES/FILLS 读不出来」），**不是**静默退化成从头探索 —— 门口那道闸是好的，
只是它后面**没有可走的路**。

**两条路，等用户点头**（这是设计决定，不是 bug 修的活儿）：

- **（甲）让 `from_py` 认这个形状**：把「读页面型」的循环翻译成 states/fills。
  有损，而且可能根本翻不出来（那份 py 的意图是「看到什么填什么」，而 states/fills 是**步骤表**）。
- **（乙）py 修站绕开 states/fills**：把**旧 py + 失败证据**直接交给 LLM 出补丁。
  这与 `graph.py:349` 那两条路「形状相同、只差 states/fills 从哪来」是**同一个口** ——
  用户已经说过「不是免费修。我允许用LLM得」。

⚠️ 无论走哪条，**真跑一趟**还需要用户给**这个站的成功文案**（`success_text`）：
它是**人**才知道的，而且**要进产物**（`template.render` 拿不到就 `ValueError`，
`agent/template.py:87`）。**不许编** —— 编出来的成功判据就是「跑到底再谎报成功」的入口。
